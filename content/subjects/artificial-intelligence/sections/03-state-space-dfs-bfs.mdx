## The state search space

<Ar>فضاء البحث عن الحالات</Ar>

<Definition term="State search space" termAr="فضاء البحث عن الحالات">
  The collection of <strong>all possible states</strong> a system can be in while searching for a solution to a given problem.

  <Ar>مجموعة <strong>كل الحالات الممكنة</strong> التي يمكن أن يكون عليها النظام أثناء البحث عن حل لمسألة معيّنة.</Ar>
</Definition>

<Grid cols={3}>
  <Card title="States" titleAr="الحالات">Each unique configuration of the system.<Ar>كل تهيئة فريدة للنظام.</Ar></Card>
  <Card title="Initial state" titleAr="الحالة الابتدائية">The starting point of the search.<Ar>نقطة بداية البحث.</Ar></Card>

  <Card title="Goal state" titleAr="الحالة الهدف">The state that meets the problem's success conditions.<Ar>الحالة التي تستوفي شروط النجاح في المسألة.</Ar></Card>
  <Card title="Operators" titleAr="العوامل">Actions (state transitions) that move from one state to another.<Ar>أفعال (انتقالات بين الحالات) تنقل من حالة إلى أخرى.</Ar></Card>

  <Card title="Search path" titleAr="مسار البحث">The sequence of states from the initial state to the goal.<Ar>تسلسل الحالات من الحالة الابتدائية إلى الهدف.</Ar></Card>
  <Card title="Search strategy" titleAr="استراتيجية البحث">The rule that picks which state to explore next: DFS, BFS, UCS, greedy, A*, bidirectional, IDS…<Ar>القاعدة التي تختار الحالة التالية التي تُستكشف: `DFS` و`BFS` و`UCS` والبحث الجشع (greedy) و`A*` والبحث ثنائي الاتجاه (bidirectional) و`IDS`…</Ar></Card>
</Grid>

The **space graph** represents all states (nodes) and transitions (edges). The **optimal solution path** is the best path to the goal. "Best" can mean the **fastest**, **shortest** (fewest steps) or **lowest-cost** path, so optimality is judged by (1) reaching the goal at all and (2) how expensive the path is.

<Ar>يمثّل **رسم فضاء الحالات (space graph)** جميع الحالات (العقد nodes) والانتقالات (الحواف edges). و**مسار الحل الأمثل (optimal solution path)** هو أفضل مسار إلى الهدف. وقد تعني كلمة «الأفضل» المسار **الأسرع**، أو **الأقصر** (أقل عدد من الخطوات)، أو **الأقل تكلفة**، لذا يُحكم على الأمثلية بـ (1) الوصول إلى الهدف أصلًا، و(2) مدى تكلفة المسار.</Ar>

<Definition term="Path cost" termAr="تكلفة المسار">
  The total weight of a path: the <strong>sum of the edge weights</strong> along it.

  <Ar>الوزن الكلي للمسار: أي <strong>مجموع أوزان الحواف</strong> على امتداده.</Ar>
</Definition>

## Graphs

<Ar>الرسوم البيانية</Ar>

A **graph** $G = (V, E)$ represents relationships: **vertices** $V$ are objects or states and **edges** $E$ are the connections between them. Graphs can be:

<Ar>يمثّل **الرسم البياني (graph)** $G = (V, E)$ العلاقات: فـ**الرؤوس (vertices)** $V$ هي الكائنات أو الحالات، و**الحواف (edges)** $E$ هي الروابط بينها. ويمكن أن تكون الرسوم البيانية:</Ar>

| Property <Ar>الخاصية</Ar> | Variants <Ar>الأنواع</Ar> |
|---|---|
| Direction <Ar>الاتجاه</Ar> | **Directed** (edges have a direction) or **undirected** <Ar>**موجَّهة** (للحواف اتجاه) أو **غير موجَّهة**</Ar> |
| Weights <Ar>الأوزان</Ar> | **Weighted** (edges carry a cost) or **unweighted** <Ar>**موزونة** (تحمل الحواف تكلفة) أو **غير موزونة**</Ar> |
| Cycles <Ar>الدورات</Ar> | **Cyclic** or **acyclic** <Ar>**دورية (cyclic)** أو **غير دورية (acyclic)**</Ar> |
| Connectivity <Ar>الاتصال</Ar> | **Connected** (a path exists between every pair) or **disconnected** <Ar>**متصلة** (يوجد مسار بين كل زوج من الرؤوس) أو **غير متصلة**</Ar> |

### Representing a graph in code

<Ar>تمثيل الرسم البياني في الشيفرة</Ar>

<SlideFigure page={18} caption="The same undirected graph as an adjacency list and as an adjacency matrix." captionAr="الرسم البياني غير الموجَّه نفسه ممثلًا بقائمة تجاور وبمصفوفة تجاور." />

| | Adjacency list <Ar>قائمة التجاور</Ar> | Adjacency matrix <Ar>مصفوفة التجاور</Ar> |
|---|---|---|
| Structure <Ar>البنية</Ar> | `{vertex: [neighbours]}` | $\lvert V \rvert \times \lvert V \rvert$ table; cell $(i, j)$ = 1 (or the weight) if there is an edge <Ar>جدول بحجم $\lvert V \rvert \times \lvert V \rvert$؛ الخلية $(i, j)$ = 1 (أو الوزن) إذا وُجدت حافة</Ar> |
| Memory <Ar>الذاكرة</Ar> | $O(\lvert V \rvert + \lvert E \rvert)$, good for sparse graphs <Ar>$O(\lvert V \rvert + \lvert E \rvert)$، مناسبة للرسوم البيانية المتناثرة (sparse)</Ar> | $O(\lvert V \rvert^2)$ |
| "Is $u$–$v$ an edge?" <Ar>«هل $u$–$v$ حافة؟»</Ar> | Scan $u$'s list <Ar>افحص قائمة $u$</Ar> | $O(1)$ lookup <Ar>بحث في $O(1)$</Ar> |
| Undirected graphs <Ar>الرسوم البيانية غير الموجَّهة</Ar> | Store each edge **both ways** <Ar>خزّن كل حافة **في الاتجاهين**</Ar> | The matrix is **symmetric** <Ar>تكون المصفوفة **متماثلة (symmetric)**</Ar> |

```python title="representations.py"
adjacency_list = {
    "A": ["B", "C"],
    "B": ["A", "D"],
    "C": ["A"],
    "D": ["B"],
}

vertices = ["A", "B", "C", "D"]
adjacency_matrix = [
    #  A  B  C  D
    [0, 1, 1, 0],  # A
    [1, 0, 0, 1],  # B
    [1, 0, 0, 0],  # C
    [0, 1, 0, 0],  # D
]
```

### Trees and traversals

<Ar>الأشجار وطرق الاجتياز</Ar>

A **tree** is a special graph: connected, acyclic, and every node except the root has exactly one parent. Visiting every node systematically is called **traversal**:

<Ar>**الشجرة (tree)** رسم بياني خاص: متصل، وغير دوري، ولكل عقدة ما عدا الجذر أمٌّ واحدة بالضبط. وتُسمى زيارة كل العقد بشكل منهجي **الاجتياز (traversal)**:</Ar>

| Traversal <Ar>الاجتياز</Ar> | Order <Ar>الترتيب</Ar> |
|---|---|
| **Pre-order** <Ar>**الترتيب القبلي**</Ar> | Root → Left → Right ← *our focus* <Ar>الجذر ← الأيسر ← الأيمن (وهو *محور تركيزنا*)</Ar> |
| In-order <Ar>الترتيب الوسطي</Ar> | Left → Root → Right <Ar>الأيسر ← الجذر ← الأيمن</Ar> |
| Post-order <Ar>الترتيب البعدي</Ar> | Left → Right → Root <Ar>الأيسر ← الأيمن ← الجذر</Ar> |

Depth-first search on a tree visits nodes in **pre-order**.

<Ar>يزور البحث بالعمق أولًا عقدَ الشجرة بـ**الترتيب القبلي (pre-order)**.</Ar>

## One algorithm, different queues

<Ar>خوارزمية واحدة وطوابير مختلفة</Ar>

<Callout type="tip" title="Don't worry!" titleAr="لا تقلق!">
  Every uninformed strategy is the <strong>same basic search loop</strong>. The <strong>only</strong> difference between them is the queuing function that decides which path leaves the list next.

  <Ar>كل استراتيجية غير مُوجَّهة هي <strong>حلقة البحث الأساسية نفسها</strong>. والفرق <strong>الوحيد</strong> بينها هو دالة الاصطفاف (queuing function) التي تقرر أي مسار يخرج من القائمة تاليًا.</Ar>
</Callout>

<Steps>

1. Put a path containing only the **start** node into the list.
   <Ar>ضع في القائمة مسارًا لا يحتوي إلا على عقدة **البداية**.</Ar>
2. If the list is empty, the search **fails**.
   <Ar>إذا كانت القائمة فارغة، **يفشل** البحث.</Ar>
3. **Remove** one path from the list, chosen by the strategy's queuing function.
   <Ar>**أزِل** مسارًا واحدًا من القائمة، تختاره دالة الاصطفاف الخاصة بالاستراتيجية.</Ar>
4. If its last node was already **visited**, discard the path and go back to step 2; otherwise mark the node as visited.
   <Ar>إذا كانت عقدته الأخيرة قد **زِيرت** من قبل، فتجاهل المسار وعُد إلى الخطوة 2؛ وإلا فعلّم العقدة على أنها مُزارة.</Ar>
5. If the last node is the **goal**, return the path.
   <Ar>إذا كانت العقدة الأخيرة هي **الهدف**، فأرجِع المسار.</Ar>
6. Otherwise **extend** the path with every neighbour, add the new paths to the list, and go back to step 2.
   <Ar>وإلا **فمدّد** المسار بكل عقدة مجاورة، وأضف المسارات الجديدة إلى القائمة، وعُد إلى الخطوة 2.</Ar>

</Steps>

| Strategy <Ar>الاستراتيجية</Ar> | Queuing function <Ar>دالة الاصطفاف</Ar> | Removes… <Ar>تُزيل…</Ar> |
|---|---|---|
| Depth-first search <Ar>البحث بالعمق أولًا</Ar> | **LIFO** (stack) <Ar>**LIFO** (مكدس)</Ar> | the newest path <Ar>أحدث مسار</Ar> |
| Breadth-first search <Ar>البحث بالعرض أولًا</Ar> | **FIFO** (queue) <Ar>**FIFO** (طابور)</Ar> | the oldest path <Ar>أقدم مسار</Ar> |
| Uniform-cost search (next lab) <Ar>البحث بالتكلفة الموحدة (السكشن القادم)</Ar> | **FIFO + priority** <Ar>**FIFO + أولوية**</Ar> | the cheapest path <Ar>أرخص مسار</Ar> |

## Depth-first search (DFS)

<Ar>البحث بالعمق أولًا (DFS)</Ar>

**LIFO (Last In, First Out)**: the last element added is the first one removed, like a stack of plates.

<Ar>**LIFO (Last In, First Out)** أي «الداخل أخيرًا يخرج أولًا»: آخر عنصر يُضاف هو أول عنصر يُزال، مثل كومة من الأطباق.</Ar>

On trees we follow **pre-order**, so children are pushed right-to-left and the **left** child ends up on top of the stack.

<Ar>في الأشجار نتبع **الترتيب القبلي (pre-order)**، لذا تُدفع الأبناء إلى المكدس من اليمين إلى اليسار، فينتهي الابن **الأيسر** في قمة المكدس.</Ar>

| Step <Ar>الخطوة</Ar> | Pop <Ar>السحب (Pop)</Ar> | Stack afterwards (top on the right) <Ar>المكدس بعدها (القمة على اليمين)</Ar> |

| 1 | 1 | 3, 2 |
| 2 | 2 | 3, 5, 4 |
| 3 | 4 | 3, 5, 8 |
| 4 | 8 | 3, 5 |
| 5 | 5 | 3, 10, 9 |

<Ar>**الحل** `[1, 3, 7, 11]` · **العقد المُزارة** `[1, 2, 4, 8, 5, 9, 10, 3, 6, 7, 11]`.</Ar>

<Ar>البحث بالعرض أولًا (BFS)</Ar>

**FIFO (First In, First Out)**: the first element added is the first one removed, like a queue at a bank.

<Ar>**FIFO (First In, First Out)** أي «الداخل أولًا يخرج أولًا»: أول عنصر يُضاف هو أول عنصر يُزال، مثل طابور الانتظار في البنك.</Ar>

  To get one unified answer for everyone, sort each node's neighbours <strong>alphabetically</strong> and add the new paths in that order. With a LIFO stack this means the alphabetically <strong>last</strong> neighbour comes off first.

  <Ar>للحصول على إجابة موحدة للجميع، رتّب العقد المجاورة لكل عقدة <strong>أبجديًا</strong> وأضف المسارات الجديدة بهذا الترتيب. ومع مكدس LIFO يعني ذلك أن العقدة المجاورة <strong>الأخيرة</strong> أبجديًا هي التي تُسحب أولًا.</Ar>

</Callout>

## Implementation: a Graph class

<Ar>التنفيذ: صنف Graph</Ar>

The lab builds one class that handles directed or undirected, weighted or unweighted graphs, stored as an adjacency list.

<Ar>يبني السكشن صنفًا واحدًا يتعامل مع الرسوم البيانية الموجَّهة أو غير الموجَّهة، والموزونة أو غير الموزونة، مخزَّنةً على شكل قائمة تجاور.</Ar>

```python title="graph.py"
class Graph:
    """Adjacency-list graph used in Labs 03 and 04."""

    def __init__(self, directed=False, weighted=False):
        self.directed = directed
        self.weighted = weighted
        self.adj = {}

    def add_vertex(self, vertex):
        self.adj.setdefault(vertex, [])

    def add_edge(self, u, v, weight=None):
        if u not in self.adj or v not in self.adj:
            raise KeyError("Both vertices must exist in the graph")
        if self.weighted and weight is None:
            raise ValueError("A weighted graph needs a weight for every edge")
        self.adj[u].append((v, weight) if self.weighted else v)
        if not self.directed:                       # undirected: store both ways
            self.adj[v].append((u, weight) if self.weighted else u)

    def get_graph(self):
        return self.adj

    def neighbours(self, vertex):
        """Neighbour names, sorted alphabetically for a unified answer."""
        items = self.adj[vertex]
        names = [n for n, _ in items] if self.weighted else list(items)
        return sorted(names)
```

### The DFS and BFS methods

<Ar>الدالتان العضوان DFS و BFS</Ar>

The two methods are identical except for **one line**: which end of the list the next path comes from.

<Ar>الدالتان العضوان (methods) متطابقتان باستثناء **سطر واحد**: من أي طرف في القائمة يأتي المسار التالي.</Ar>

```python title="graph.py (continued)" {4,18}
    def dfs(self, start, goal):
        fringe, visited = [[start]], []
        while fringe:
            path = fringe.pop()                  # LIFO: newest path
            node = path[-1]
            if node in visited:
                continue
            visited.append(node)
            if node == goal:
                return path, visited
            for n in self.neighbours(node):
                fringe.append(path + [n])
        return None, visited

    def bfs(self, start, goal):
        fringe, visited = [[start]], []
        while fringe:
            path = fringe.pop(0)                 # FIFO: oldest path
            node = path[-1]
            if node in visited:
                continue
            visited.append(node)
            if node == goal:
                return path, visited
            for n in self.neighbours(node):
                fringe.append(path + [n])
        return None, visited
```

### Formulate the problem and test

<Ar>صياغة المسألة واختبارها</Ar>

```python title="test_graph.py"
g = Graph(directed=True, weighted=True)
for v in "SABCDG":
    g.add_vertex(v)
for u, v, w in [("S", "B", 3), ("S", "A", 2), ("S", "D", 5), ("A", "C", 4),
                ("C", "G", 2), ("C", "D", 1), ("B", "D", 4), ("D", "G", 5)]:
    g.add_edge(u, v, w)

print(g.dfs("S", "G"))  # (['S', 'D', 'G'], ['S', 'D', 'G'])
print(g.bfs("S", "G"))  # (['S', 'D', 'G'], ['S', 'A', 'B', 'D', 'C', 'G'])
```

<Callout type="tip" title="Performance note" titleAr="ملاحظة حول الأداء">
  <code>list.pop(0)</code> is $O(n)$. For large graphs use <code>collections.deque</code> and <code>popleft()</code>, and store <code>visited</code> as a <strong>set</strong> for $O(1)$ membership checks.

  <Ar>تكلفة <code>list.pop(0)</code> هي $O(n)$. في الرسوم البيانية الكبيرة استخدم <code>collections.deque</code> و <code>popleft()</code>، وخزّن <code>visited</code> على شكل <strong>مجموعة (set)</strong> لفحص الانتماء في $O(1)$.</Ar>
</Callout>

<Takeaways>

- A search problem = states + initial state + goal state + operators; the **strategy** decides the order of exploration.
  <Ar>مسألة البحث = الحالات + الحالة الابتدائية + الحالة الهدف + العوامل (operators)؛ و**الاستراتيجية** تحدد ترتيب الاستكشاف.</Ar>
- Graphs are stored as an **adjacency list** (compact) or an **adjacency matrix** (fast edge lookup).
  <Ar>تُخزَّن الرسوم البيانية على شكل **قائمة تجاور** (مضغوطة) أو **مصفوفة تجاور** (بحث سريع عن الحواف).</Ar>
- DFS uses a **LIFO** stack and BFS a **FIFO** queue; everything else in the code is the same.
  <Ar>يستخدم DFS مكدس **LIFO** ويستخدم BFS طابور **FIFO**؛ وكل ما عدا ذلك في الشيفرة متطابق.</Ar>
- Neither DFS nor BFS considers edge weights, so on weighted graphs they may miss the cheapest path.
  <Ar>لا يأخذ DFS ولا BFS أوزان الحواف في الحسبان، لذا قد يفوتهما أرخص مسار في الرسوم البيانية الموزونة.</Ar>

</Takeaways>

<Exercise title="Undirected version" titleAr="النسخة غير الموجَّهة" level="medium">

Rebuild the lab graph as **undirected** (same weights) and run BFS from S to G. Does the visited order change?

<Ar>أعد بناء الرسم البياني الخاص بالسكشن على أنه **غير موجَّه** (بالأوزان نفسها) وشغّل BFS من S إلى G. هل يتغير ترتيب الزيارة؟</Ar>

<Solution>

With undirected edges, each node also lists the nodes that point to it. BFS still expands S first (neighbours A, B, D), then A (neighbours C, S), B (D, S), D (B, C, G, S) and C. The visited order stays `[S, A, B, D, C, G]` and the solution is still `S → D → G`, because the extra back-edges only lead to nodes that are already visited.

<Ar>مع الحواف غير الموجَّهة، تضم قائمة كل عقدة أيضًا العقدَ التي تشير إليها. ويظل BFS يوسّع S أولًا (جيرانها A, B, D)، ثم A (جيرانها C, S)، ثم B (D, S)، ثم D (B, C, G, S)، ثم C. ويبقى ترتيب الزيارة `[S, A, B, D, C, G]` ويظل الحل `S → D → G`، لأن الحواف العكسية الإضافية لا تؤدي إلا إلى عقد سبقت زيارتها.</Ar>

<Exercise title="Adjacency matrix method" titleAr="دالة عضو لمصفوفة التجاور" level="medium">

Add a method `to_matrix()` to the `Graph` class that returns the vertex order and the adjacency matrix (weights for weighted graphs, 1 for unweighted, 0 for no edge).

<Ar>أضف دالة عضوًا (method) باسم `to_matrix()` إلى الصنف `Graph` تُرجع ترتيب الرؤوس ومصفوفة التجاور (الأوزان للرسوم البيانية الموزونة، و 1 لغير الموزونة، و 0 عند عدم وجود حافة).</Ar>

<Solution>

```python
def to_matrix(self):
    order = sorted(self.adj)
    index = {v: i for i, v in enumerate(order)}
    m = [[0] * len(order) for _ in order]
    for u, items in self.adj.items():
        for item in items:
            v, w = item if self.weighted else (item, 1)
            m[index[u]][index[v]] = w
    return order, m
```
