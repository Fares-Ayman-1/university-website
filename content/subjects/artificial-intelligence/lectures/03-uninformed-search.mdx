## Tree search

<Ar>البحث الشجري</Ar>

Search is an **offline, simulated exploration** of the state space. Starting from the initial state, we **expand** states: we generate their successors, then choose which one to expand next. The choice is the **search strategy**.

<Ar>البحث هو **استكشاف محاكى (simulated) يجري مسبقًا دون اتصال (offline)** لفضاء الحالات. فبدءًا من الحالة الابتدائية **نوسّع (expand)** الحالات: أي نولّد الحالات التالية لها، ثم نختار أيها نوسّع بعد ذلك. وهذا الاختيار هو **استراتيجية البحث (search strategy)**.</Ar>

```text title="TREE-SEARCH"
function TREE-SEARCH(problem, strategy) returns a solution, or failure
  initialize the search tree using the initial state of problem
  loop do
    if there are no candidates for expansion then return failure
    choose a leaf node for expansion according to strategy
    if the node contains a goal state then return the corresponding solution
    else expand the node and add the resulting nodes to the search tree
```

### States versus nodes

<Ar>الحالات مقابل العقد</Ar>

<Definition term="State vs. node" termAr="الحالة مقابل العقدة">
  A <strong>state</strong> is a representation of a physical configuration. A <strong>node</strong> is a data structure in the search tree; it holds a state plus its <strong>parent</strong>, the <strong>action</strong> that produced it, its <strong>depth</strong> and its <strong>path cost</strong> $g(n)$.

  <Ar><strong>الحالة (state)</strong> تمثيل لتهيئة فيزيائية. أما <strong>العقدة (node)</strong> فبنية بيانات في شجرة البحث؛ تحمل حالةً بالإضافة إلى <strong>العقدة الأم (parent)</strong>، و<strong>الفعل (action)</strong> الذي أنتجها، و<strong>عمقها (depth)</strong>، و<strong>تكلفة مسارها (path cost)</strong> $g(n)$.</Ar>
</Definition>

States do not have parents, depths or path costs; nodes do. The same state can appear in many nodes, reached by different paths.

<Ar>ليس للحالات عقد أم ولا أعماق ولا تكاليف مسار؛ بل هذه كلها للعقد. ويمكن أن تظهر الحالة نفسها في عقد كثيرة، يُوصَل إليها عبر مسارات مختلفة.</Ar>

### General tree search with a fringe

<Ar>البحث الشجري العام باستخدام الحافة</Ar>

The **fringe** (or frontier) is the collection of generated nodes that have not been expanded yet. All the strategies below use the same algorithm and differ only in **where new nodes are inserted** into the fringe.

<Ar>**الحافة (fringe)** (أو frontier) هي مجموعة العقد المولَّدة التي لم تُوسَّع بعد. تستخدم جميع الاستراتيجيات التالية الخوارزمية نفسها، ولا تختلف إلا في **موضع إدراج العقد الجديدة** في الحافة.</Ar>

```text title="TREE-SEARCH with a fringe"
function TREE-SEARCH(problem, fringe) returns a solution, or failure
  fringe ← INSERT(MAKE-NODE(INITIAL-STATE[problem]), fringe)
  loop do
    if fringe is empty then return failure
    node ← REMOVE-FRONT(fringe)
    if GOAL-TEST(problem, STATE(node)) then return node
    fringe ← INSERT-ALL(EXPAND(node, problem), fringe)

function EXPAND(node, problem) returns a set of nodes
  successors ← the empty set
  for each action, result in SUCCESSOR-FN(problem, STATE[node]) do
    s ← a new NODE
    PARENT-NODE[s] ← node; ACTION[s] ← action; STATE[s] ← result
    PATH-COST[s] ← PATH-COST[node] + STEP-COST(node, action, s)
    DEPTH[s] ← DEPTH[node] + 1
    add s to successors
  return successors
```

## Evaluating search strategies

<Ar>تقييم استراتيجيات البحث</Ar>

A strategy is defined by the **order of node expansion**. We judge it on four criteria:

<Ar>تُعرَّف الاستراتيجية بـ**ترتيب توسيع العقد**، ونحكم عليها وفق أربعة معايير:</Ar>

| Criterion <Ar>المعيار</Ar> | Question <Ar>السؤال</Ar> |
|---|---|
| **Completeness** <Ar>**الاكتمال**</Ar> | Does it always find a solution if one exists? <Ar>هل تجد دائمًا حلًّا إن وُجد؟</Ar> |
| **Time complexity** <Ar>**التعقيد الزمني**</Ar> | How many nodes are generated or expanded? <Ar>كم عدد العقد التي تُولَّد أو تُوسَّع؟</Ar> |
| **Space complexity** <Ar>**التعقيد المكاني**</Ar> | What is the maximum number of nodes in memory? <Ar>ما الحد الأقصى لعدد العقد في الذاكرة؟</Ar> |
| **Optimality** <Ar>**الأمثلية**</Ar> | Does it always find a least-cost solution? <Ar>هل تجد دائمًا الحل الأقل تكلفة؟</Ar> |

Time and space are measured with three quantities:

<Ar>يُقاس الزمن والمساحة بثلاث كميات:</Ar>

- $b$: the maximum **branching factor** of the search tree,
  <Ar>$b$: أقصى **معامل تفرّع (branching factor)** لشجرة البحث،</Ar>
- $d$: the **depth of the least-cost solution**,
  <Ar>$d$: **عمق الحل الأقل تكلفة**،</Ar>
- $m$: the **maximum depth** of the state space (possibly $\infty$).
  <Ar>$m$: **أقصى عمق** لفضاء الحالات (وقد يكون $\infty$).</Ar>

**Uninformed** (blind) strategies use only the information in the problem definition. They cannot tell whether one non-goal state is "closer" to the goal than another; that is what informed search adds next.

<Ar>تستخدم الاستراتيجيات **غير المُوجَّهة (uninformed)** (العمياء) المعلومات الموجودة في تعريف المسألة فقط. فهي لا تستطيع أن تعرف هل حالةٌ ما ليست هدفًا «أقرب» إلى الهدف من حالة أخرى؛ وهذا ما يضيفه البحث المُوجَّه (informed search) لاحقًا.</Ar>

## Breadth-first search (BFS)

<Ar>البحث بالعرض أولًا (BFS)</Ar>

**Expand the shallowest unexpanded node.** The fringe is a **FIFO queue**: new successors go to the back.

<Ar>**وسّع العقدة الأقل عمقًا من بين العقد غير الموسَّعة.** الحافة هنا **طابور (queue) من نوع FIFO**: تُضاف الحالات التالية الجديدة إلى نهايته.</Ar>

<Tree tree="A(B(D,E),C(F,G))" order="A,B,C,D,E,F,G" caption="BFS expands level by level: A, then B and C, then D, E, F, G." />

| Property <Ar>الخاصية</Ar> | BFS <Ar>البحث بالعرض أولًا</Ar> |
|---|---|
| Complete? <Ar>مكتمل؟</Ar> | **Yes**, if $b$ is finite <Ar>**نعم**، إذا كان $b$ منتهيًا</Ar> |
| Time <Ar>الزمن</Ar> | $1 + b + b^2 + \dots + b^d + b(b^d - 1) = O(b^{d+1})$, exponential in $d$ <Ar>$1 + b + b^2 + \dots + b^d + b(b^d - 1) = O(b^{d+1})$، أي أُسّي بالنسبة إلى $d$</Ar> |
| Space <Ar>المساحة</Ar> | $O(b^{d+1})$: it keeps every node in memory <Ar>$O(b^{d+1})$: إذ يحتفظ بكل عقدة في الذاكرة</Ar> |
| Optimal? <Ar>أمثل؟</Ar> | **Yes** if every step costs 1; not optimal in general <Ar>**نعم** إذا كانت تكلفة كل خطوة 1؛ وليس أمثل في الحالة العامة</Ar> |

The extra $b(b^d - 1)$ term appears because the goal test is applied when a node is **expanded**: every node at depth $d$ except the goal gets expanded first. Testing nodes when they are **generated** reduces the cost to $O(b^d)$.

<Ar>يظهر الحد الإضافي $b(b^d - 1)$ لأن اختبار الهدف يُطبَّق عند **توسيع** العقدة: فكل عقدة عند العمق $d$ ما عدا الهدف تُوسَّع أولًا. أما اختبار العقد عند **توليدها** فيخفض التكلفة إلى $O(b^d)$.</Ar>

<Callout type="warning" title="Space is the real problem" titleAr="المساحة هي المشكلة الحقيقية">
  At 100 MB of new nodes per second, one day of search fills 8,640 GB. BFS runs out of memory long before it runs out of time.

  <Ar>بمعدل 100 MB من العقد الجديدة في الثانية، يملأ يومٌ واحد من البحث 8,640 GB. فتنفد ذاكرة BFS قبل أن ينفد وقته بكثير.</Ar>
</Callout>

## Uniform-cost search (UCS)

<Ar>البحث بالتكلفة الموحدة (UCS)</Ar>

**Expand the least-cost unexpanded node.** The fringe is a **priority queue ordered by path cost** $g(n)$, lowest first. When all step costs are equal, UCS behaves exactly like BFS.

<Ar>**وسّع العقدة غير الموسَّعة الأقل تكلفة.** الحافة هنا **طابور أولوية (priority queue) مرتَّب حسب تكلفة المسار** $g(n)$، الأقل أولًا. وعندما تتساوى تكاليف جميع الخطوات، يتصرف UCS تمامًا مثل BFS.</Ar>

Let $C^*$ be the cost of the optimal solution and $\epsilon$ the smallest step cost.

<Ar>لتكن $C^*$ تكلفة الحل الأمثل، و $\epsilon$ أصغر تكلفة خطوة.</Ar>

| Property <Ar>الخاصية</Ar> | UCS <Ar>البحث بالتكلفة الموحدة</Ar> |
|---|---|
| Complete? <Ar>مكتمل؟</Ar> | **Yes**, if every step cost $\ge \epsilon > 0$ <Ar>**نعم**، إذا كانت تكلفة كل خطوة $\ge \epsilon > 0$</Ar> |
| Time <Ar>الزمن</Ar> | Number of nodes with $g \le C^*$: $O(b^{\lceil C^*/\epsilon \rceil})$ <Ar>عدد العقد التي تحقق $g \le C^*$: $O(b^{\lceil C^*/\epsilon \rceil})$</Ar> |
| Space <Ar>المساحة</Ar> | Same: $O(b^{\lceil C^*/\epsilon \rceil})$ <Ar>مثل الزمن: $O(b^{\lceil C^*/\epsilon \rceil})$</Ar> |
| Optimal? <Ar>أمثل؟</Ar> | **Yes**, because nodes are expanded in increasing order of $g(n)$ <Ar>**نعم**، لأن العقد تُوسَّع بترتيب تصاعدي لقيمة $g(n)$</Ar> |

<Callout type="note">
  The condition $\epsilon > 0$ matters: with zero-cost steps, UCS could loop forever along a path of zero-cost actions.

  <Ar>للشرط $\epsilon > 0$ أهمية: فمع وجود خطوات تكلفتها صفر، قد يدور UCS إلى الأبد على مسار من الأفعال صفرية التكلفة.</Ar>
</Callout>

## Depth-first search (DFS)

<Ar>البحث بالعمق أولًا (DFS)</Ar>

**Expand the deepest unexpanded node.** The fringe is a **LIFO stack**: successors go to the front.

<Ar>**وسّع العقدة غير الموسَّعة الأعمق.** الحافة هنا **مكدس (stack) من نوع LIFO**: تُضاف الحالات التالية إلى مقدمته.</Ar>

<Tree
  tree="A(B(D(H,I),E(J,K)),C(F(L,M),G(N,O)))"
  order="A,B,D,H,I,E,J,K,C,F,L,M"
  path="A,C,F,M"
  goal="M"
  caption="DFS dives to the left-most leaf first and backtracks. With goal M it expands 12 nodes; subtrees that are fully explored can be removed from memory."
/>

| Property <Ar>الخاصية</Ar> | DFS <Ar>البحث بالعمق أولًا</Ar> |
|---|---|
| Complete? <Ar>مكتمل؟</Ar> | **No**: it fails in infinite-depth spaces and in spaces with loops. Avoiding repeated states along the current path makes it complete in **finite** spaces. <Ar>**لا**: يفشل في الفضاءات لا نهائية العمق وفي الفضاءات التي تحتوي على حلقات. وتجنّب الحالات المتكررة على المسار الحالي يجعله مكتملًا في الفضاءات **المنتهية**.</Ar> |
| Time <Ar>الزمن</Ar> | $O(b^m)$: terrible if $m \gg d$, but if solutions are dense it may be much faster than BFS <Ar>$O(b^m)$: سيئ جدًا إذا كان $m \gg d$، لكن إذا كانت الحلول كثيفة فقد يكون أسرع بكثير من BFS</Ar> |
| Space <Ar>المساحة</Ar> | $O(bm)$: **linear space!** <Ar>$O(bm)$: **مساحة خطية!**</Ar> |
| Optimal? <Ar>أمثل؟</Ar> | **No** <Ar>**لا**</Ar> |

## Depth-limited search (DLS)

<Ar>البحث محدود العمق (DLS)</Ar>

DLS is DFS with a **depth limit** $l$: nodes at depth $l$ are treated as having no successors. It solves DFS's infinite-path problem, but it returns two kinds of failure:

<Ar>البحث DLS هو DFS مع **حدٍّ للعمق (depth limit)** $l$: تُعامَل العقد عند العمق $l$ كأنها بلا حالات تالية. وهو يحل مشكلة المسارات اللانهائية في DFS، لكنه يُرجع نوعين من الإخفاق:</Ar>

- **failure**: there is no solution at all;
  <Ar>**الإخفاق (failure)**: لا يوجد حل على الإطلاق؛</Ar>
- **cutoff**: there is no solution *within the limit*.
  <Ar>**القطع (cutoff)**: لا يوجد حل *ضمن الحد*.</Ar>

```text title="DEPTH-LIMITED-SEARCH"
function DEPTH-LIMITED-SEARCH(problem, limit) returns soln / failure / cutoff
  return RECURSIVE-DLS(MAKE-NODE(INITIAL-STATE[problem]), problem, limit)

function RECURSIVE-DLS(node, problem, limit) returns soln / failure / cutoff
  cutoff-occurred? ← false
  if GOAL-TEST(problem, STATE[node]) then return node
  else if DEPTH[node] = limit then return cutoff
  else for each successor in EXPAND(node, problem) do
    result ← RECURSIVE-DLS(successor, problem, limit)
    if result = cutoff then cutoff-occurred? ← true
    else if result ≠ failure then return result
  if cutoff-occurred? then return cutoff else return failure
```

DLS is complete only if $l \ge d$, and it is not optimal. Choosing $l$ needs knowledge of the problem; for Romania, 20 cities means any solution has length $\le 19$.

<Ar>لا يكون DLS مكتملًا إلا إذا كان $l \ge d$، وهو ليس أمثل. ويحتاج اختيار $l$ إلى معرفة بالمسألة؛ ففي مسألة رومانيا، وجود 20 مدينة يعني أن طول أي حل $\le 19$.</Ar>

## Iterative deepening search (IDS)

<Ar>البحث بالتعميق التكراري (IDS)</Ar>

IDS runs DLS with limits $0, 1, 2, \dots$ until it finds a solution. It combines the **linear memory of DFS** with the **completeness and optimality of BFS**.

<Ar>يشغّل IDS البحث DLS بالحدود $0, 1, 2, \dots$ حتى يجد حلًّا. وهو يجمع بين **الذاكرة الخطية لـ DFS** و**اكتمال BFS وأمثليته**.</Ar>

```text title="ITERATIVE-DEEPENING-SEARCH"
function ITERATIVE-DEEPENING-SEARCH(problem) returns a solution
  for depth ← 0 to ∞ do
    result ← DEPTH-LIMITED-SEARCH(problem, depth)
    if result ≠ cutoff then return result
```

| Limit <Ar>الحد</Ar> | Nodes expanded, in order <Ar>العقد الموسَّعة بالترتيب</Ar> |
|---|---|
| $l = 0$ | A |
| $l = 1$ | A, B, C |
| $l = 2$ | A, B, D, E, C, F, G |
| $l = 3$ | A, B, D, H, I, E, J, K, C, F, L, M … (stops at goal M) <Ar>A, B, D, H, I, E, J, K, C, F, L, M … (يتوقف عند الهدف M)</Ar> |

| Property <Ar>الخاصية</Ar> | IDS <Ar>البحث بالتعميق التكراري</Ar> |
|---|---|
| Complete? <Ar>مكتمل؟</Ar> | **Yes** <Ar>**نعم**</Ar> |
| Time <Ar>الزمن</Ar> | $(d+1)b^0 + d\,b^1 + (d-1)b^2 + \dots + b^d = O(b^d)$ |
| Space <Ar>المساحة</Ar> | $O(bd)$ |
| Optimal? <Ar>أمثل؟</Ar> | **Yes**, if every step costs 1 (it can be modified to explore a uniform-cost tree) <Ar>**نعم**، إذا كانت تكلفة كل خطوة 1 (ويمكن تعديله لاستكشاف شجرة بالتكلفة الموحدة)</Ar> |

Re-generating the upper levels sounds wasteful, but most nodes live at the bottom level, so the overhead is small. For $b = 10$ and $d = 5$, with the solution at the far right leaf (not counting the root):

<Ar>قد تبدو إعادة توليد المستويات العليا إهدارًا، لكن معظم العقد توجد في المستوى السفلي، لذا تكون التكلفة الإضافية صغيرة. فعندما $b = 10$ و $d = 5$، والحل في أقصى ورقة على اليمين (دون احتساب الجذر):</Ar>

$$
\begin{aligned}
N(\text{IDS}) &= 50 + 400 + 3{,}000 + 20{,}000 + 100{,}000 = 123{,}450 \\
N(\text{BFS}) &= 10 + 100 + 1{,}000 + 10{,}000 + 100{,}000 + 999{,}990 = 1{,}111{,}100
\end{aligned}
$$

IDS wins here because BFS (testing goals on expansion) also generates the nodes at depth $d + 1$.

<Ar>يتفوق IDS هنا لأن BFS (الذي يختبر الهدف عند التوسيع) يولّد أيضًا العقد عند العمق $d + 1$.</Ar>

## Summary of algorithms

<Ar>ملخص الخوارزميات</Ar>

| Criterion <Ar>المعيار</Ar> | Breadth-first <Ar>بالعرض أولًا</Ar> | Uniform-cost <Ar>بالتكلفة الموحدة</Ar> | Depth-first <Ar>بالعمق أولًا</Ar> | Depth-limited <Ar>محدود العمق</Ar> | Iterative deepening <Ar>بالتعميق التكراري</Ar> |
|---|---|---|---|---|---|
| Complete? <Ar>مكتمل؟</Ar> | Yes* <Ar>نعم\*</Ar> | Yes* <Ar>نعم\*</Ar> | No <Ar>لا</Ar> | Yes, if $l \ge d$ <Ar>نعم، إذا كان $l \ge d$</Ar> | Yes <Ar>نعم</Ar> |
| Time <Ar>الزمن</Ar> | $b^{d+1}$ | $b^{\lceil C^*/\epsilon \rceil}$ | $b^m$ | $b^l$ | $b^d$ |
| Space <Ar>المساحة</Ar> | $b^{d+1}$ | $b^{\lceil C^*/\epsilon \rceil}$ | $bm$ | $bl$ | $bd$ |
| Optimal? <Ar>أمثل؟</Ar> | Yes* <Ar>نعم\*</Ar> | Yes <Ar>نعم</Ar> | No <Ar>لا</Ar> | No <Ar>لا</Ar> | Yes* <Ar>نعم\*</Ar> |

\* BFS is complete if $b$ is finite; UCS if step costs $\ge \epsilon > 0$. BFS and IDS are optimal when all step costs are equal.

<Ar>\* يكون BFS مكتملًا إذا كان $b$ منتهيًا، و UCS إذا كانت تكاليف الخطوات $\ge \epsilon > 0$. ويكون BFS و IDS أمثلين عندما تتساوى تكاليف جميع الخطوات.</Ar>

## Repeated states and graph search

<Ar>الحالات المتكررة والبحث في الرسم البياني</Ar>

If the state space has loops or reversible actions, tree search keeps regenerating the same states.

<Ar>إذا احتوى فضاء الحالات على حلقات أو أفعال قابلة للعكس، فإن البحث الشجري يظل يعيد توليد الحالات نفسها.</Ar>

<SlideFigure page={49} caption="A linear chain of states (left) becomes an exponentially large search tree (right) when repeated states are not detected." captionAr="تتحول سلسلة خطية من الحالات (يسارًا) إلى شجرة بحث كبيرة أُسّيًّا (يمينًا) عندما لا تُكتشف الحالات المتكررة." />

**Graph search** fixes this with a **closed set** of states that have already been expanded:

<Ar>يعالج **البحث في الرسم البياني (graph search)** ذلك بـ**مجموعة مغلقة (closed set)** تضم الحالات التي سبق توسيعها:</Ar>

```text title="GRAPH-SEARCH"
function GRAPH-SEARCH(problem, fringe) returns a solution, or failure
  closed ← an empty set
  fringe ← INSERT(MAKE-NODE(INITIAL-STATE[problem]), fringe)
  loop do
    if fringe is empty then return failure
    node ← REMOVE-FRONT(fringe)
    if GOAL-TEST(problem, STATE[node]) then return node
    if STATE[node] is not in closed then
      add STATE[node] to closed
      fringe ← INSERT-ALL(EXPAND(node, problem), fringe)
```

## Implementation in Python

<Ar>التنفيذ بلغة Python</Ar>

All four strategies share one loop; only the fringe changes.

<Ar>تشترك الاستراتيجيات الأربع في حلقة واحدة؛ ولا يتغير إلا نوع الحافة.</Ar>

```python title="uninformed_search.py"
from collections import deque
import heapq

GRAPH = {
    "A": {"B": 1, "C": 1}, "B": {"D": 1, "E": 1}, "C": {"F": 1, "G": 1},
    "D": {}, "E": {}, "F": {}, "G": {},
}

def path_to(parents, node):
    path = [node]
    while parents[path[-1]] is not None:
        path.append(parents[path[-1]])
    return path[::-1]

def bfs(graph, start, goal):
    fringe, parents = deque([start]), {start: None}
    while fringe:
        node = fringe.popleft()                      # FIFO
        if node == goal:
            return path_to(parents, node)
        for child in graph[node]:
            if child not in parents:                 # graph search: skip seen states
                parents[child] = node
                fringe.append(child)
    return None

def dfs(graph, start, goal):
    fringe, parents = [start], {start: None}
    while fringe:
        node = fringe.pop()                          # LIFO
        if node == goal:
            return path_to(parents, node)
        for child in reversed(list(graph[node])):    # keep left-to-right order
            if child not in parents:
                parents[child] = node
                fringe.append(child)
    return None

def ucs(graph, start, goal):
    fringe, best = [(0, start, [start])], {start: 0}
    while fringe:
        cost, node, path = heapq.heappop(fringe)     # lowest g(n) first
        if node == goal:
            return path, cost
        for child, step in graph[node].items():
            new_cost = cost + step
            if new_cost < best.get(child, float("inf")):
                best[child] = new_cost
                heapq.heappush(fringe, (new_cost, child, path + [child]))
    return None

def dls(graph, node, goal, limit, path=()):
    path = path + (node,)
    if node == goal:
        return list(path)
    if limit == 0:
        return "cutoff"
    cutoff = False
    for child in graph[node]:
        result = dls(graph, child, goal, limit - 1, path)
        if result == "cutoff":
            cutoff = True
        elif result is not None:
            return result
    return "cutoff" if cutoff else None

def ids(graph, start, goal, max_depth=50):
    for depth in range(max_depth + 1):
        result = dls(graph, start, goal, depth)
        if result != "cutoff":
            return result
    return None

print(bfs(GRAPH, "A", "G"))   # ['A', 'C', 'G']
print(ids(GRAPH, "A", "G"))   # ['A', 'C', 'G']
```

<Takeaways>

- All tree-search strategies share one loop; they differ only in **which fringe node is expanded next**.
  <Ar>تشترك جميع استراتيجيات البحث الشجري في حلقة واحدة، ولا تختلف إلا في **أي عقدة من الحافة تُوسَّع تاليًا**.</Ar>
- **BFS** and **UCS** are complete and optimal (under their conditions) but need exponential **memory**.
  <Ar>**BFS** و **UCS** مكتملان وأمثلان (ضمن شروطهما) لكنهما يحتاجان إلى **ذاكرة** أُسّية.</Ar>
- **DFS** needs only linear memory but is neither complete nor optimal.
  <Ar>يحتاج **DFS** إلى ذاكرة خطية فقط، لكنه ليس مكتملًا ولا أمثل.</Ar>
- **IDS** uses linear space and not much more time than BFS, so it is the preferred uninformed method when the solution depth is unknown.
  <Ar>يستخدم **IDS** مساحة خطية وزمنًا لا يزيد كثيرًا على زمن BFS، لذا فهو الطريقة غير المُوجَّهة المفضلة عندما يكون عمق الحل مجهولًا.</Ar>
- **Graph search** (a closed set) can be exponentially more efficient than tree search when states repeat.
  <Ar>يمكن أن يكون **البحث في الرسم البياني** (مع مجموعة مغلقة) أكفأ أُسّيًّا من البحث الشجري عندما تتكرر الحالات.</Ar>

</Takeaways>

<Exercise title="IDS overhead" titleAr="التكلفة الإضافية لـ IDS" level="medium">

For a complete binary tree ($b = 2$) with the goal at depth $d = 3$, how many nodes does IDS generate in total, counting the root at every iteration? Compare with BFS testing on generation.

<Ar>لشجرة ثنائية كاملة ($b = 2$) والهدف عند العمق $d = 3$، كم عدد العقد التي يولّدها IDS إجمالًا، مع احتساب الجذر في كل تكرار؟ قارن ذلك مع BFS الذي يختبر الهدف عند التوليد.</Ar>

<Solution>

IDS generates $(d+1)b^0 + d\,b^1 + (d-1)b^2 + b^3 = 4 \cdot 1 + 3 \cdot 2 + 2 \cdot 4 + 1 \cdot 8 = 26$ nodes in the worst case.

<Ar>يولّد IDS $(d+1)b^0 + d\,b^1 + (d-1)b^2 + b^3 = 4 \cdot 1 + 3 \cdot 2 + 2 \cdot 4 + 1 \cdot 8 = 26$ عقدة في أسوأ الحالات.</Ar>

BFS (goal test on generation) generates $1 + 2 + 4 + 8 = 15$ nodes. With $b = 2$ the overhead ratio is large; it shrinks as $b$ grows, which is why IDS is attractive for big branching factors.

<Ar>أما BFS (مع اختبار الهدف عند التوليد) فيولّد $1 + 2 + 4 + 8 = 15$ عقدة. وعندما $b = 2$ تكون نسبة التكلفة الإضافية كبيرة، لكنها تتقلص كلما كبر $b$، ولهذا يكون IDS جذابًا لمعاملات التفرّع الكبيرة.</Ar>

</Solution>

</Exercise>

<Exercise title="Pick a strategy" titleAr="اختر استراتيجية" level="medium">

A puzzle has branching factor 10, solutions at depth 12, many states repeat, and you have very little memory. Which uninformed strategy would you use, and why?

<Ar>لغزٌ معامل تفرّعه 10، وحلوله عند العمق 12، وتتكرر فيه حالات كثيرة، ولديك ذاكرة قليلة جدًا. أي استراتيجية غير مُوجَّهة ستستخدم، ولماذا؟</Ar>

<Solution>

**Iterative deepening search**, ideally with checks for repeated states along the current path. It needs only $O(bd)$ memory. BFS would need about $10^{12}$ nodes in memory. Plain DFS might dive down an infinite or very deep branch and is not optimal. IDS finds the shallowest solution and re-expands only a small fraction of nodes when $b = 10$.

<Ar>**البحث بالتعميق التكراري (iterative deepening)**، ويُفضَّل مع فحص الحالات المتكررة على المسار الحالي. فهو لا يحتاج إلا إلى ذاكرة $O(bd)$، بينما يحتاج BFS إلى نحو $10^{12}$ عقدة في الذاكرة. وقد يغوص DFS العادي في فرع لا نهائي أو عميق جدًا، كما أنه ليس أمثل. أما IDS فيجد الحل الأقل عمقًا ولا يعيد توسيع إلا جزء صغير من العقد عندما $b = 10$.</Ar>

</Solution>
