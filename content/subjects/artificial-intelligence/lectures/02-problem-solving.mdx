## Problem-solving agents

<Ar>وكلاء حل المسائل</Ar>

A problem-solving agent is a restricted kind of **goal-based agent**. It does not react percept by percept. It thinks ahead: it finds a whole sequence of actions that reaches the goal, then carries that sequence out.

<Ar>وكيل حل المسائل (problem-solving agent) نوع مقيَّد من **الوكيل القائم على الهدف (goal-based agent)**. فهو لا يستجيب لكل إدراك على حدة، بل يفكر مسبقًا: يجد تسلسلًا كاملًا من الأفعال يصل إلى الهدف، ثم ينفّذ ذلك التسلسل.</Ar>

<Steps>

1. **Formulate a goal** from the current situation, e.g. "be in Bucharest".
   <Ar>**صياغة الهدف** انطلاقًا من الوضع الحالي، مثل «الوصول إلى بوخارست (Bucharest)».</Ar>
2. **Formulate the problem**: decide which states and actions to consider.
   <Ar>**صياغة المسألة**: تحديد الحالات والأفعال التي ستؤخذ في الحسبان.</Ar>
3. **Search** for a sequence of actions that reaches the goal.
   <Ar>**البحث** عن تسلسل من الأفعال يصل إلى الهدف.</Ar>
4. **Execute** the solution, one action at a time.
   <Ar>**تنفيذ** الحل، فعلًا واحدًا في كل مرة.</Ar>

</Steps>

```text title="SIMPLE-PROBLEM-SOLVING-AGENT"
function SIMPLE-PROBLEM-SOLVING-AGENT(percept) returns an action
  static: seq      — an action sequence, initially empty
          state    — description of the current world state
          goal     — a goal, initially null
          problem  — a problem formulation

  state ← UPDATE-STATE(state, percept)
  if seq is empty then
      goal    ← FORMULATE-GOAL(state)
      problem ← FORMULATE-PROBLEM(state, goal)
      seq     ← SEARCH(problem)
  action ← FIRST(seq)
  seq    ← REST(seq)
  return action
```

Notice that the agent ignores its percepts while it executes `seq`. This is called **open-loop** execution. It is safe only when the environment is fully observable and deterministic, so nothing unexpected can happen.

<Ar>لاحظ أن الوكيل يتجاهل إدراكاته أثناء تنفيذ `seq`، وهذا ما يُسمى التنفيذ **بالحلقة المفتوحة (open-loop)**. ولا يكون آمنًا إلا عندما تكون البيئة قابلة للملاحظة كليًا وحتمية، بحيث لا يمكن أن يحدث شيء غير متوقع.</Ar>

## Problem types

<Ar>أنواع المسائل</Ar>

How hard a problem is depends on what the agent knows about the world and its actions.

<Ar>تتوقف صعوبة المسألة على ما يعرفه الوكيل عن العالم وعن أفعاله.</Ar>

| Environment <Ar>البيئة</Ar> | Problem type <Ar>نوع المسألة</Ar> | What a solution looks like <Ar>شكل الحل</Ar> |
|---|---|---|
| Deterministic, fully observable <Ar>حتمية، وقابلة للملاحظة كليًا</Ar> | **Single-state** <Ar>**الحالة الواحدة**</Ar> | The agent knows exactly which state it is in, so a solution is a fixed **sequence** of actions. <Ar>يعرف الوكيل بالضبط الحالة التي هو فيها، لذا فالحل **تسلسل** ثابت من الأفعال.</Ar> |
| Non-observable (sensorless) <Ar>غير قابلة للملاحظة (عديمة المستشعرات sensorless)</Ar> | **Conformant** <Ar>**متوافقة**</Ar> | The agent may not know where it is; it reasons about **sets of states**. The solution (if any) is still a sequence that works from every possible state. <Ar>قد لا يعرف الوكيل أين هو، فيستدل على **مجموعات من الحالات**. ويظل الحل (إن وُجد) تسلسلًا ينجح انطلاقًا من كل حالة ممكنة.</Ar> |
| Nondeterministic and/or partially observable <Ar>غير حتمية و/أو قابلة للملاحظة جزئيًا</Ar> | **Contingency** <Ar>**طوارئ**</Ar> | Percepts bring new information during execution, so the solution is a **contingent plan** (a policy with branches). Search and execution are often interleaved. <Ar>تأتي الإدراكات بمعلومات جديدة أثناء التنفيذ، لذا فالحل **خطة طوارئ (contingent plan)** (أي سياسة (policy) ذات تفرعات). وكثيرًا ما يتداخل البحث والتنفيذ.</Ar> |
| Unknown state space <Ar>فضاء حالات مجهول</Ar> | **Exploration** (online) <Ar>**استكشاف** (آني، online)</Ar> | The agent must act to discover which states and actions even exist. <Ar>يجب على الوكيل أن يتصرف ليكتشف ما هي الحالات والأفعال الموجودة أصلًا.</Ar> |

### The vacuum world, four ways

<Ar>عالم المكنسة بأربع طرق</Ar>

The vacuum world with two squares has **8 states**: 2 robot positions × 2 dirt statuses for A × 2 for B.

<Ar>لعالم المكنسة ذي المربعين **8 حالات**: موضعان للروبوت × حالتان للاتساخ في A × حالتان في B.</Ar>

<SlideFigure page={10} caption="The eight states of the two-square vacuum world. In state 5 the robot is in A, A is clean and B is dirty." captionAr="الحالات الثماني لعالم المكنسة ذي المربعين. في الحالة 5 يكون الروبوت في A، و A نظيف و B متسخ." />

  <Card title="Single-state" titleAr="الحالة الواحدة" tag="start in #5">
    The agent knows it is in state 5, so the solution is <code>[Right, Suck]</code>.

    <Ar>يعرف الوكيل أنه في الحالة 5، لذا فالحل هو <code>[Right, Suck]</code>.</Ar>
  </Card>
  <Card title="Conformant" titleAr="المتوافقة" tag="start anywhere">
    The start is any of the 8 states. <code>Right</code> always leads to one of the states 2, 4, 6 or 8. The solution is <code>[Right, Suck, Left, Suck]</code>, which works from every start.

    <Ar>قد تكون البداية أيًّا من الحالات الثماني. يؤدي <code>Right</code> دائمًا إلى إحدى الحالات 2 أو 4 أو 6 أو 8. والحل هو <code>[Right, Suck, Left, Suck]</code>، وهو ينجح من أي بداية.</Ar>
  </Card>

    <Ar>قد يؤدي <code>Suck</code> أحيانًا إلى اتساخ سجادة نظيفة، ولا يستشعر الوكيل إلا مربعه فقط. ويحتاج الحل إلى تفرّع: <code>[Right, if dirt then Suck]</code>.</Ar>
  </Card>
  <Card title="Exploration" titleAr="الاستكشاف" tag="online">
    The agent does not know the layout or what its actions do, so it must experiment to build its own map.

    <Ar>لا يعرف الوكيل تخطيط المكان ولا ما تفعله أفعاله، لذا عليه أن يجرّب ليبني خريطته الخاصة.</Ar>

## Formulating a single-state problem

<Ar>صياغة مسألة الحالة الواحدة</Ar>

<Definition term="Problem" termAr="المسألة">
  A problem is defined by four items: an <strong>initial state</strong>, a <strong>successor function</strong>, a <strong>goal test</strong> and a <strong>path cost</strong>.

  <Ar>تُعرَّف المسألة بأربعة عناصر: <strong>الحالة الابتدائية (initial state)</strong>، و<strong>دالة الحالات التالية (successor function)</strong>، و<strong>اختبار الهدف (goal test)</strong>، و<strong>تكلفة المسار (path cost)</strong>.</Ar>
</Definition>

| Component <Ar>المكوّن</Ar> | Meaning <Ar>المعنى</Ar> | Romania example <Ar>مثال رومانيا</Ar> |
|---|---|---|
| **Initial state** <Ar>**الحالة الابتدائية**</Ar> | Where the agent starts <Ar>المكان الذي يبدأ منه الوكيل</Ar> | `In(Arad)` |
| **Successor function** $S(x)$ <Ar>**دالة الحالات التالية** $S(x)$</Ar> | The set of action–state pairs reachable from $x$ <Ar>مجموعة أزواج (فعل، حالة) التي يمكن الوصول إليها من $x$</Ar> | $S(\text{Arad}) = \{\langle \text{Arad} \rightarrow \text{Zerind}, \text{Zerind} \rangle, \dots\}$ |
| **Goal test** <Ar>**اختبار الهدف**</Ar> | Explicit (a specific state) or implicit (a property) <Ar>صريح (حالة محددة) أو ضمني (خاصية)</Ar> | $x = $ `In(Bucharest)`; or implicit, like `NoDirt(x)` <Ar>$x =$ `In(Bucharest)`؛ أو ضمني، مثل `NoDirt(x)`</Ar> |
| **Path cost** <Ar>**تكلفة المسار**</Ar> | Additive cost of a path; each step cost $c(x, a, y) \ge 0$ <Ar>تكلفة جمعية للمسار؛ وتكون تكلفة كل خطوة $c(x, a, y) \ge 0$</Ar> | Sum of kilometres driven <Ar>مجموع الكيلومترات المقطوعة</Ar> |

A **solution** is a sequence of actions that leads from the initial state to a goal state. An **optimal solution** has the lowest path cost of all solutions.

<Ar>**الحل (solution)** تسلسل من الأفعال يقود من الحالة الابتدائية إلى حالة هدف. و**الحل الأمثل (optimal solution)** هو الحل صاحب أقل تكلفة مسار بين جميع الحلول.</Ar>

$$
g(\text{path}) = \sum_{i} c(x_i, a_i, x_{i+1}), \qquad c(x, a, y) \ge 0
$$

Here is the same formulation in Python, and it is the shape the lab code uses:

<Ar>إليك الصياغة نفسها بلغة Python، وهي الشكل الذي تستخدمه شيفرة السكشن:</Ar>

```python title="romania_problem.py"
ROADS = {
    "Arad": {"Zerind": 75, "Sibiu": 140, "Timisoara": 118},
    "Sibiu": {"Arad": 140, "Oradea": 151, "Fagaras": 99, "Rimnicu Vilcea": 80},
    "Fagaras": {"Sibiu": 99, "Bucharest": 211},
    "Rimnicu Vilcea": {"Sibiu": 80, "Pitesti": 97, "Craiova": 146},
    "Pitesti": {"Rimnicu Vilcea": 97, "Craiova": 138, "Bucharest": 101},
    # ... remaining cities omitted for brevity
}

class RouteProblem:
    def __init__(self, initial, goal, roads):
        self.initial, self.goal, self.roads = initial, goal, roads

    def successors(self, state):
        """Return (action, next_state) pairs."""
        return [(f"{state} -> {city}", city) for city in self.roads.get(state, {})]

    def goal_test(self, state):
        return state == self.goal

    def step_cost(self, state, action, next_state):
        return self.roads[state][next_state]

problem = RouteProblem("Arad", "Bucharest", ROADS)
print(problem.successors("Arad"))
```

## Selecting a state space

<Ar>اختيار فضاء الحالات</Ar>

The real world is far too complex to search directly, so the state space must be **abstracted**:

<Ar>العالم الحقيقي أعقد بكثير من أن نبحث فيه مباشرةً، لذا يجب **تجريد (abstract)** فضاء الحالات:</Ar>

- An **abstract state** stands for a set of real states. "In Arad" ignores the weather, the radio station and your exact position in town.
  <Ar>**الحالة المجردة (abstract state)** تمثل مجموعة من الحالات الحقيقية؛ فالحالة «في أراد» تتجاهل الطقس ومحطة الراديو وموقعك الدقيق في المدينة.</Ar>
- An **abstract action** stands for a complex combination of real actions. "Arad → Zerind" covers all routes, detours and rest stops.
  <Ar>**الفعل المجرد (abstract action)** يمثل تركيبة معقدة من الأفعال الحقيقية؛ فالفعل `Arad → Zerind` يشمل جميع الطرق والتحويلات ومحطات الاستراحة.</Ar>
- An **abstract solution** corresponds to a set of real paths that are solutions in the real world.
  <Ar>**الحل المجرد (abstract solution)** يقابل مجموعة من المسارات الحقيقية التي تُعدّ حلولًا في العالم الحقيقي.</Ar>

<Callout type="tip" title="What makes a good abstraction" titleAr="ما الذي يجعل التجريد جيدًا">
  It must be <strong>valid</strong>: any real state "in Arad" must be able to reach some real state "in Zerind". It must also be <strong>useful</strong>: each abstract action should be easier to carry out than the original problem.

  <Ar>يجب أن يكون <strong>صالحًا (valid)</strong>: أي أن كل حالة حقيقية «في أراد» يجب أن تتمكن من الوصول إلى حالة حقيقية ما «في زيرند». ويجب أن يكون أيضًا <strong>مفيدًا (useful)</strong>: أي أن تنفيذ كل فعل مجرد يجب أن يكون أسهل من المسألة الأصلية.</Ar>
</Callout>

## Example problems

<Ar>أمثلة على المسائل</Ar>

### The vacuum world

<Ar>عالم المكنسة</Ar>

<SlideFigure page={17} caption="The vacuum-world state space. L = Left, R = Right, S = Suck." captionAr="فضاء حالات عالم المكنسة. L = Left، و R = Right، و S = Suck." />

| | Formulation <Ar>الصياغة</Ar> |
|---|---|
| **States** <Ar>**الحالات**</Ar> | Robot location and dirt status of each square (ignore dirt amounts): $2 \times 2^2 = 8$ states <Ar>موقع الروبوت وحالة الاتساخ لكل مربع (مع تجاهل كمية الأوساخ): $2 \times 2^2 = 8$ حالات</Ar> |
| **Actions** <Ar>**الأفعال**</Ar> | `Left`, `Right`, `Suck`, `NoOp` |
| **Goal test** <Ar>**اختبار الهدف**</Ar> | No dirt in any square <Ar>لا أوساخ في أي مربع</Ar> |
| **Path cost** <Ar>**تكلفة المسار**</Ar> | 1 per action (0 for `NoOp`) <Ar>1 لكل فعل (و 0 للفعل `NoOp`)</Ar> |

### The 8-puzzle

<Ar>لغز الثمانية (8-puzzle)</Ar>

<SlideFigure page={22} caption="Slide tiles into the blank until the board matches the goal state." captionAr="حرّك القطع إلى الخانة الفارغة حتى تطابق اللوحةُ الحالةَ الهدف." />

| | Formulation <Ar>الصياغة</Ar> |
|---|---|
| **States** <Ar>**الحالات**</Ar> | The location of each tile and the blank (ignore intermediate positions) <Ar>موقع كل قطعة والخانة الفارغة (مع تجاهل المواضع الوسيطة)</Ar> |
| **Actions** <Ar>**الأفعال**</Ar> | Move the **blank** left, right, up or down (ignore unjamming etc.) <Ar>تحريك **الخانة الفارغة** يسارًا أو يمينًا أو أعلى أو أسفل (مع تجاهل فكّ القطع العالقة وما شابه)</Ar> |
| **Goal test** <Ar>**اختبار الهدف**</Ar> | The state equals the given goal configuration <Ar>تساوي الحالةُ تهيئةَ الهدف المعطاة</Ar> |
| **Path cost** <Ar>**تكلفة المسار**</Ar> | 1 per move <Ar>1 لكل حركة</Ar> |

The 8-puzzle has $9!/2 = 181{,}440$ reachable states. Finding the optimal solution for the general $n$-puzzle family is **NP-hard**, which is why it is a classic test bed for search algorithms.

<Ar>للغز الثمانية $9!/2 = 181{,}440$ حالة يمكن الوصول إليها. وإيجاد الحل الأمثل لعائلة الألغاز العامة `n-puzzle` مسألة **NP-hard**، ولهذا فهو ميدان اختبار كلاسيكي لخوارزميات البحث.</Ar>

<Callout type="note" title="Why move the blank?" titleAr="لماذا نحرّك الخانة الفارغة؟">
  Describing the actions as moves of the single blank gives just 4 possible actions. Describing them as moves of each tile would give up to 8 tiles × 4 directions, most of them illegal.

  <Ar>وصف الأفعال بأنها حركات للخانة الفارغة الوحيدة يعطي 4 أفعال ممكنة فقط. أما وصفها بأنها حركات لكل قطعة فقد يعطي ما يصل إلى 8 قطع × 4 اتجاهات، ومعظمها غير مسموح به.</Ar>
</Callout>

### Robotic assembly

<Ar>التجميع الروبوتي</Ar>

<SlideFigure page={23} caption="A robot arm assembling an object: a continuous problem." captionAr="ذراع روبوتية تجمّع جسمًا: مسألة متصلة (continuous)." />

| | Formulation <Ar>الصياغة</Ar> |
|---|---|
| **States** <Ar>**الحالات**</Ar> | Real-valued coordinates of the robot's joint angles, plus the parts of the object being assembled <Ar>إحداثيات ذات قيم حقيقية لزوايا مفاصل الروبوت، بالإضافة إلى أجزاء الجسم الذي يجري تجميعه</Ar> |
| **Actions** <Ar>**الأفعال**</Ar> | Continuous motions of the robot joints <Ar>حركات متصلة لمفاصل الروبوت</Ar> |
| **Goal test** <Ar>**اختبار الهدف**</Ar> | Complete assembly (without the robot included in it!) <Ar>اكتمال التجميع (دون أن يكون الروبوت نفسه جزءًا منه!)</Ar> |
| **Path cost** <Ar>**تكلفة المسار**</Ar> | Time to execute <Ar>زمن التنفيذ</Ar> |

Unlike the previous examples, this state space is **continuous**, so it has to be discretised or handled with specialised planning methods.

<Ar>على عكس الأمثلة السابقة، فضاء الحالات هذا **متصل (continuous)**، لذا يجب تقطيعه إلى قيم منفصلة (discretised) أو التعامل معه بأساليب تخطيط متخصصة.</Ar>

<Takeaways>

- A problem-solving agent formulates a **goal**, then a **problem**, **searches** for a solution and **executes** it.
  <Ar>يصوغ وكيل حل المسائل **هدفًا**، ثم **مسألة**، ثم **يبحث** عن حل و**ينفّذه**.</Ar>
- Problems are **single-state**, **conformant**, **contingency** or **exploration** problems, depending on observability and determinism.
  <Ar>تكون المسائل مسائل **حالة واحدة** أو **متوافقة** أو **طوارئ** أو **استكشاف**، بحسب قابلية الملاحظة والحتمية.</Ar>
- A problem = **initial state + successor function + goal test + path cost**; a solution is an action sequence that reaches a goal.
  <Ar>المسألة = **الحالة الابتدائية + دالة الحالات التالية + اختبار الهدف + تكلفة المسار**؛ والحل تسلسل أفعال يصل إلى هدف.</Ar>
- Good formulations **abstract away** irrelevant detail while keeping every abstract action realisable.
  <Ar>الصياغات الجيدة **تُجرِّد** التفاصيل غير ذات الصلة مع إبقاء كل فعل مجرد قابلًا للتحقيق.</Ar>

</Takeaways>

<Exercise title="Formulate the water-jug problem" titleAr="صُغ مسألة إبريقَي الماء" level="medium">

You have a 4-litre jug and a 3-litre jug, no markings, and a tap. The goal is exactly 2 litres in the 4-litre jug. Give the states, initial state, actions, goal test and path cost.

<Ar>لديك إبريق سعته 4 لترات وإبريق سعته 3 لترات، دون علامات قياس، وصنبور ماء. والهدف هو الحصول على 2 لتر بالضبط في إبريق الـ4 لترات. حدِّد الحالات، والحالة الابتدائية، والأفعال، واختبار الهدف، وتكلفة المسار.</Ar>

<Solution>

- **States**: pairs $(x, y)$ with $x \in \{0..4\}$ litres in the big jug and $y \in \{0..3\}$ in the small jug.
  <Ar>**الحالات**: أزواج $(x, y)$ حيث $x \in \{0..4\}$ عدد اللترات في الإبريق الكبير و $y \in \{0..3\}$ في الإبريق الصغير.</Ar>
- **Initial state**: $(0, 0)$.
  <Ar>**الحالة الابتدائية**: $(0, 0)$.</Ar>
- **Actions**: fill either jug, empty either jug, pour one jug into the other until the source is empty or the target is full.
  <Ar>**الأفعال**: ملء أيٍّ من الإبريقين، أو تفريغ أيٍّ منهما، أو صبّ أحدهما في الآخر حتى يفرغ المصدر أو يمتلئ الهدف.</Ar>
- **Goal test**: $x = 2$ (any $y$).
  <Ar>**اختبار الهدف**: $x = 2$ (بأي قيمة لـ $y$).</Ar>
- **Path cost**: 1 per action.
  <Ar>**تكلفة المسار**: 1 لكل فعل.</Ar>

One solution: (0,0) → (0,3) → (3,0) → (3,3) → (4,2) → (0,2) → (2,0).

<Ar>أحد الحلول: `(0,0) → (0,3) → (3,0) → (3,3) → (4,2) → (0,2) → (2,0)`.</Ar>

</Solution>

</Exercise>

<Exercise title="Count the states" titleAr="احسب عدد الحالات" level="easy">

How many states does the vacuum world have if there are **n** squares in a row instead of 2?

<Ar>كم عدد حالات عالم المكنسة إذا كان هناك **n** من المربعات في صف واحد بدلًا من 2؟</Ar>

<Solution>

The robot can be in any of the $n$ squares, and each square is independently dirty or clean: $n \cdot 2^n$ states. For $n = 2$ that gives $2 \cdot 4 = 8$, matching the lecture.

<Ar>يمكن أن يكون الروبوت في أي من المربعات الـ $n$، وكل مربع متسخ أو نظيف بشكل مستقل: أي $n \cdot 2^n$ حالة. وعندما $n = 2$ يعطي ذلك $2 \cdot 4 = 8$، وهو ما يطابق المحاضرة.</Ar>

</Solution>

</Exercise>

<Exercise title="Which problem type?" titleAr="ما نوع المسألة؟" level="easy">

A robot vacuum has **no sensors at all** but knows exactly what its actions do. Which problem type is this, and what does a solution look like?

<Ar>مكنسة روبوتية **ليس لها أي مستشعرات على الإطلاق** لكنها تعرف بالضبط ما تفعله أفعالها. ما نوع هذه المسألة، وكيف يبدو الحل؟</Ar>

<Solution>

It is a **conformant** (sensorless) problem. The agent reasons about the set of states it might be in, and the solution is one fixed action sequence that reaches a goal from every state in that set, for example `[Right, Suck, Left, Suck]`.

<Ar>إنها مسألة **متوافقة (conformant)** (عديمة المستشعرات). يستدل الوكيل على مجموعة الحالات التي قد يكون فيها، والحل تسلسل أفعال واحد ثابت يصل إلى هدف من كل حالة في تلك المجموعة، مثل `[Right, Suck, Left, Suck]`.</Ar>

</Solution>

</Exercise>
