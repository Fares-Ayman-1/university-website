## What group functions do

<Ar>ما الذي تفعله دوال التجميع</Ar>

Group functions operate on **sets of rows** and return **one result per group**. Without `GROUP BY`, the whole table (after `WHERE`) is a single group.

<Ar>تعمل دوال التجميع (group functions) على **مجموعات من الصفوف** وتُعيد **نتيجة واحدة لكل مجموعة**. ودون `GROUP BY`، يكون الجدول كله (بعد تطبيق `WHERE`) مجموعة واحدة.</Ar>

| Function <Ar>الدالة</Ar> | Returns <Ar>تُعيد</Ar> | Data types <Ar>أنواع البيانات</Ar> |
|---|---|---|
| `AVG([DISTINCT] n)` | Average <Ar>المتوسط</Ar> | Numeric <Ar>رقمية</Ar> |
| `SUM([DISTINCT] n)` | Total <Ar>المجموع</Ar> | Numeric <Ar>رقمية</Ar> |
| `MIN(expr)` / `MAX(expr)` | Smallest / largest value <Ar>أصغر / أكبر قيمة</Ar> | Numeric, **character**, **date** <Ar>رقمية، **نصية**، **تاريخ**</Ar> |
| `COUNT(*)` | Number of rows <Ar>عدد الصفوف</Ar> | Any <Ar>أي نوع</Ar> |
| `COUNT([DISTINCT] expr)` | Number of **non-null** values <Ar>عدد القيم **غير الفارغة (non-null)**</Ar> | Any <Ar>أي نوع</Ar> |
| `STDDEV(n)` / `VARIANCE(n)` | Standard deviation / variance <Ar>الانحراف المعياري / التباين</Ar> | Numeric <Ar>رقمية</Ar> |

```sql
SELECT AVG(salary), MAX(salary), MIN(salary), SUM(salary)
FROM   employees
WHERE  job_id LIKE '%REP%';
-- 8150   11000   6000   32600      (Abel, Taylor, Grant, Fay)

SELECT MIN(hire_date), MAX(hire_date)
FROM   employees;                   -- earliest and latest hire dates
```

### COUNT, DISTINCT and NULL

<Ar>الدالة COUNT والكلمة DISTINCT والقيمة NULL</Ar>

```sql
SELECT COUNT(*)              FROM employees WHERE department_id = 50;   -- 5 rows
SELECT COUNT(commission_pct) FROM employees WHERE department_id = 80;   -- 3 non-null values
SELECT COUNT(DISTINCT department_id) FROM employees;                   -- 7 departments
```

The last query returns 7, not 8, because Grant's NULL department isn't a value. **Group functions ignore NULLs** (except `COUNT(*)`):

<Ar>يُعيد الاستعلام الأخير 7 وليس 8، لأن القسم الفارغ (NULL) الخاص بـ Grant ليس قيمة. **تتجاهل دوال التجميع القيم الفارغة (NULLs)** (باستثناء `COUNT(*)`):</Ar>

```sql
SELECT AVG(commission_pct)          FROM employees;   -- .2125   (= .85 / 4 commission earners)
SELECT AVG(NVL(commission_pct, 0))  FROM employees;   -- .0425   (= .85 / 20 employees)
```

<Callout type="warning" title="Which average do you want?" titleAr="أي متوسط تريد؟">
  <code>AVG(commission_pct)</code> is the average <em>among people who have a commission</em>. To average over <em>all</em> employees, turn NULLs into 0 with <code>NVL</code> first.

  <Ar><code>AVG(commission_pct)</code> هو المتوسط <em>بين الأشخاص الذين لديهم عمولة</em>. ولحساب المتوسط على <em>كل</em> الموظفين، حوِّل القيم الفارغة (NULLs) إلى 0 باستخدام <code>NVL</code> أولًا.</Ar>
</Callout>

## GROUP BY

<Ar>عبارة GROUP BY</Ar>

`GROUP BY` divides the rows into groups that share the same values, and the group functions are then computed **per group**.

<Ar>تقسّم `GROUP BY` الصفوف إلى مجموعات تشترك في القيم نفسها، ثم تُحسب دوال التجميع **لكل مجموعة**.</Ar>

```sql title="syntax"
SELECT   column, group_function(column)
FROM     table
[WHERE   condition]
[GROUP BY group_by_expression]
[HAVING  group_condition]
[ORDER BY column];
```

```sql
SELECT   department_id, AVG(salary)
FROM     employees
GROUP BY department_id;
```

{/* data-table */}
| DEPARTMENT_ID <Ar>رقم القسم</Ar> | AVG(SALARY) <Ar>متوسط الراتب</Ar> |
|---|---|
| 10 | 4400 |
| 20 | 9500 |
| 50 | 3500 |
| 60 | 6400 |
| 80 | 10033.33 |
| 90 | 19333.33 |
| 110 | 10150 |
| (null) | 7000 |

NULL forms its **own group** (Grant). The `GROUP BY` column **doesn't have to appear** in the SELECT list (`SELECT AVG(salary) … GROUP BY department_id` is legal), though the output is harder to read.

<Ar>تُكوِّن NULL **مجموعة خاصة بها** (Grant). ولا **يُشترط ظهور** عمود `GROUP BY` في قائمة `SELECT` (فالجملة `SELECT AVG(salary) … GROUP BY department_id` صحيحة)، وإن كانت المخرجات أصعب في القراءة.</Ar>

### Grouping by several columns

<Ar>التجميع حسب عدة أعمدة</Ar>

```sql
SELECT   department_id, job_id, SUM(salary)
FROM     employees
WHERE    department_id > 40
GROUP BY department_id, job_id
ORDER BY department_id;
```

{/* data-table */}
| DEPT <Ar>القسم</Ar> | JOB_ID <Ar>رمز الوظيفة</Ar> | SUM(SALARY) <Ar>مجموع الرواتب</Ar> |
|---|---|---|
| 50 | ST_CLERK | 11700 |
| 50 | ST_MAN | 5800 |
| 60 | IT_PROG | 19200 |
| 80 | SA_MAN | 10500 |
| 80 | SA_REP | 19600 |
| 90 | AD_PRES | 24000 |
| 90 | AD_VP | 34000 |
| 110 | AC_ACCOUNT | 8300 |
| 110 | AC_MGR | 12000 |

### Illegal grouped queries

<Ar>الاستعلامات المُجمَّعة غير الصحيحة</Ar>

<Callout type="warning" title="The golden rule" titleAr="القاعدة الذهبية">
  Every column or expression in the SELECT list that is <strong>not</strong> inside a group function <strong>must</strong> appear in GROUP BY.

  <Ar>كل عمود أو تعبير في قائمة <code>SELECT</code> <strong>ليس</strong> داخل دالة تجميع <strong>يجب</strong> أن يظهر في <code>GROUP BY</code>.</Ar>
</Callout>

```sql
SELECT department_id, COUNT(last_name) FROM employees;
-- ORA-00937: not a single-group group function      → add GROUP BY department_id

SELECT department_id, job_id, COUNT(last_name)
FROM   employees GROUP BY department_id;
-- ORA-00979: not a GROUP BY expression               → add job_id to GROUP BY (or remove it)
```

## HAVING: restricting groups

<Ar>HAVING: تقييد المجموعات</Ar>

`WHERE` filters **rows before** grouping, and it **can't** contain group functions:

<Ar>تُصفّي `WHERE` **الصفوف قبل** التجميع، و**لا يمكن** أن تحتوي على دوال تجميع:</Ar>

```sql
SELECT department_id, AVG(salary) FROM employees
WHERE  AVG(salary) > 8000                       -- ORA-00934: group function is not allowed here
GROUP BY department_id;
```

`HAVING` filters **groups after** grouping. Oracle (1) groups the rows, (2) applies the group functions, (3) keeps the groups that satisfy `HAVING`.

<Ar>تُصفّي `HAVING` **المجموعات بعد** التجميع؛ إذ يقوم Oracle بـ (1) تجميع الصفوف، ثم (2) تطبيق دوال التجميع، ثم (3) إبقاء المجموعات التي تحقق شرط `HAVING`.</Ar>

```sql
SELECT   department_id, MAX(salary)
FROM     employees
GROUP BY department_id
HAVING   MAX(salary) > 10000;
-- 20 13000 · 80 11000 · 90 24000 · 110 12000

SELECT   job_id, SUM(salary) PAYROLL
FROM     employees
WHERE    job_id NOT LIKE '%REP%'        -- row filter first
GROUP BY job_id
HAVING   SUM(salary) > 13000            -- then group filter
ORDER BY SUM(salary);
-- IT_PROG 19200 · AD_PRES 24000 · AD_VP 34000
```

| Clause <Ar>العبارة</Ar> | Runs <Ar>وقت التنفيذ</Ar> | Filters <Ar>ما تُصفّيه</Ar> |
|---|---|---|
| `WHERE` | Before grouping <Ar>قبل التجميع</Ar> | Individual **rows**; no group functions <Ar>**الصفوف** الفردية؛ دون دوال تجميع</Ar> |
| `GROUP BY` | | Forms the groups <Ar>تُكوِّن المجموعات</Ar> |
| `HAVING` | After grouping <Ar>بعد التجميع</Ar> | Whole **groups**; group functions allowed <Ar>**المجموعات** كاملة؛ ويُسمح بدوال التجميع</Ar> |
| `ORDER BY` | Last <Ar>في النهاية</Ar> | Sorts the final result <Ar>ترتّب النتيجة النهائية</Ar> |

## Nesting group functions

<Ar>تداخل دوال التجميع</Ar>

Group functions can be nested **two levels** deep, and then a `GROUP BY` is required:

<Ar>يمكن أن تتداخل دوال التجميع حتى عمق **مستويين**، وعندها تكون `GROUP BY` إلزامية:</Ar>

```sql
SELECT   MAX(AVG(salary))
FROM     employees
GROUP BY department_id;       -- 19333.33  (department 90)
```

<Takeaways>

- Group functions return **one value per group**. `MIN`/`MAX` also work on text and dates.
  <Ar>تُعيد دوال التجميع **قيمة واحدة لكل مجموعة**. وتعمل `MIN`/`MAX` أيضًا على النصوص والتواريخ.</Ar>
- `COUNT(*)` counts rows, `COUNT(expr)` counts **non-null** values, and `DISTINCT` counts unique values.
  <Ar>تَعُدّ `COUNT(*)` الصفوف، وتَعُدّ `COUNT(expr)` القيم **غير الفارغة (non-null)**، وتَعُدّ `DISTINCT` القيم الفريدة.</Ar>
- Group functions **ignore NULLs**; use `NVL` to include them.
  <Ar>تتجاهل دوال التجميع **القيم الفارغة (NULLs)**؛ استخدم `NVL` لتضمينها.</Ar>
- Non-aggregated SELECT columns **must** be in `GROUP BY`; NULL forms its own group.
  <Ar>أعمدة `SELECT` غير المُجمَّعة **يجب** أن تكون في `GROUP BY`؛ وتُكوِّن NULL مجموعة خاصة بها.</Ar>
- `WHERE` filters rows **before** grouping; `HAVING` filters groups **after** it.
  <Ar>تُصفّي `WHERE` الصفوف **قبل** التجميع، وتُصفّي `HAVING` المجموعات **بعده**.</Ar>

</Takeaways>

## Practice

<Ar>تدريب</Ar>

<Exercise title="Department statistics" titleAr="إحصاءات الأقسام" level="easy">

For each department, show the number of employees and the average salary rounded to the nearest whole number, for departments with **more than two** employees. Sort by average salary, highest first.

<Ar>لكل قسم، اعرض عدد الموظفين ومتوسط الراتب مُقرَّبًا إلى أقرب عدد صحيح، للأقسام التي بها **أكثر من موظفَين اثنين**. رتّب النتائج حسب متوسط الراتب، الأعلى أولًا.</Ar>

<Solution>

```sql
SELECT   department_id, COUNT(*) "Employees", ROUND(AVG(salary)) "Avg Salary"
FROM     employees
GROUP BY department_id
HAVING   COUNT(*) > 2
ORDER BY 3 DESC;
-- 90 3 19333 · 80 3 10033 · 60 3 6400 · 50 5 3500
```

</Solution>

</Exercise>

<Exercise title="Spot the mistake" titleAr="اكتشف الخطأ" level="medium">

Fix this query: `SELECT job_id, AVG(salary) FROM employees WHERE AVG(salary) > 10000;`

<Ar>أصلح هذا الاستعلام: `SELECT job_id, AVG(salary) FROM employees WHERE AVG(salary) > 10000;`</Ar>

<Solution>

There are two problems. A group function can't appear in WHERE, and `job_id` isn't grouped.

<Ar>هناك مشكلتان: لا يمكن أن تظهر دالة تجميع في `WHERE`، والعمود `job_id` غير مُجمَّع.</Ar>

```sql
SELECT   job_id, AVG(salary)
FROM     employees
GROUP BY job_id
HAVING   AVG(salary) > 10000;
-- AD_PRES 24000 · AD_VP 17000 · SA_MAN 10500 · MK_MAN 13000 · AC_MGR 12000
```

</Solution>

</Exercise>

<Exercise title="Guidelines quiz from the slides" titleAr="اختبار الإرشادات من الشرائح" level="easy">

True or false: (1) you can't use a column alias in GROUP BY; (2) the GROUP BY column must be in SELECT; (3) WHERE can exclude rows before grouping; (4) GROUP BY guarantees the order of the result.

<Ar>صواب أم خطأ: (1) لا يمكنك استخدام الاسم المستعار للعمود في `GROUP BY`؛ (2) يجب أن يكون عمود `GROUP BY` في `SELECT`؛ (3) يمكن لـ `WHERE` استبعاد صفوف قبل التجميع؛ (4) تضمن `GROUP BY` ترتيب النتيجة.</Ar>

<Solution>

(1) **True** in Oracle 11g, because GROUP BY is evaluated before the SELECT list. (2) **False**. (3) **True**. (4) **False**: use ORDER BY whenever you need a specific order.

<Ar>(1) **صواب** في Oracle 11g، لأن `GROUP BY` تُقيَّم قبل قائمة `SELECT`. (2) **خطأ**. (3) **صواب**. (4) **خطأ**: استخدم `ORDER BY` كلما احتجت إلى ترتيب معيّن.</Ar>

</Solution>

</Exercise>
