## Oracle Database 11g at a glance

The labs follow Oracle's *SQL Fundamentals I* course. Oracle Database 11g is an **object-relational** DBMS (ORDBMS). It is fully relational, and it adds user-defined types, objects and large multimedia data types. Its focus areas are **manageability**, **high availability**, **performance**, **security** and **information integration**. It sits inside a wider product family: Fusion Middleware, Enterprise Manager Grid Control and BI Publisher.

## Relational concepts

Dr. **E. F. Codd** proposed the relational model in **1970**. It has three parts:

- a collection of objects, or **relations** (tables),
- a set of **operators** that act on relations,
- **data integrity** rules for accuracy and consistency.

<Definition term="Relational database">
  A collection of relations, i.e. <strong>two-dimensional tables</strong>, managed by the Oracle server.
</Definition>

Designing a database goes from the client's mental model, to an **entity model** (ER diagram), to a **table model**, to **tables on disk**.

### ER diagrams in Oracle's notation

<SlideFigure page={21} caption="'Assign one or more employees to a department… some departments do not yet have employees.'" />

| Convention | Meaning |
|---|---|
| Entity in a soft box, **singular, uppercase** name | `EMPLOYEE`, `DEPARTMENT` |
| Attribute in **singular, lowercase** | `number`, `name`, `job title` |
| `#` | Part of the **primary unique identifier** (UID); `(#)` is a secondary UID |
| `*` | **Mandatory** attribute |
| `o` | **Optional** attribute |
| Solid line end / dashed line end | The relationship is mandatory / optional on that side |
| Crow's foot | "One or more" (the *many* side) |

### Relating tables

Each row is uniquely identified by its **primary key**, and a **foreign key** links a row to the primary key of a row in another (or the same) table. `EMPLOYEES.department_id` is a foreign key to `DEPARTMENTS.department_id`.

<SlideFigure page={24} caption="Relational database terminology on the EMPLOYEES table." />

| # | Term | In the figure |
|---|---|---|
| 1 | **Row** (tuple) | All the data for one employee |
| 2 | **Primary key** column | `EMPLOYEE_ID`, unique for every row |
| 3 | **Non-key** column | e.g. `SALARY` |
| 4 | **Foreign key** column | `DEPARTMENT_ID`, which refers to DEPARTMENTS |
| 5 | **Field** | The intersection of one row and one column |
| 6 | **NULL** field | A field with no value |

## SQL

**SQL** (Structured Query Language) is the **ANSI standard** language for relational databases. It is efficient, easy to learn, and **functionally complete**: one language defines, retrieves and manipulates data.

```sql
SELECT department_name
FROM   departments;
```

| Category | Statements | Purpose |
|---|---|---|
| **DML**: data manipulation | `SELECT`, `INSERT`, `UPDATE`, `DELETE`, `MERGE` | Read and change rows |
| **DDL**: data definition | `CREATE`, `ALTER`, `DROP`, `RENAME`, `TRUNCATE`, `COMMENT` | Create and change structures |
| **DCL**: data control | `GRANT`, `REVOKE` | Give and remove privileges |
| **Transaction control** | `COMMIT`, `ROLLBACK`, `SAVEPOINT` | Make DML changes permanent or undo them |

**Tools:** the primary lab tool is **Oracle SQL Developer**, a free graphical IDE. The **SQL\*Plus** command line works too.

<Steps>

1. Install Oracle Database (Express Edition is free) and **SQL Developer**.
2. In SQL Developer, create a **new connection**: user `hr`, its password, host `localhost`, port `1521`, and the service name of your install.
3. Expand **Tables** in the connection tree to browse `EMPLOYEES`, `DEPARTMENTS` and the rest.
4. Open a **SQL Worksheet**, type a statement and press **Ctrl+Enter** to run it.

</Steps>

<Takeaways>

- A relational database is a set of **tables** linked by **primary and foreign keys**; Oracle 11g is an **ORDBMS**.
- Oracle ERDs mark UIDs with `#`, mandatory attributes with `*` and optional ones with `o`.
- SQL statements fall into **DML**, **DDL**, **DCL** and **transaction control**.
- Every lab queries the **HR** schema, mostly `EMPLOYEES` and `DEPARTMENTS`.

</Takeaways>

## Practice

<Exercise title="Classify the statements" level="easy">

Classify each statement: `TRUNCATE`, `MERGE`, `SAVEPOINT`, `REVOKE`, `COMMENT`, `SELECT`.

<Solution>

`TRUNCATE`: DDL · `MERGE`: DML · `SAVEPOINT`: transaction control · `REVOKE`: DCL · `COMMENT`: DDL · `SELECT`: DML (data retrieval).

</Solution>

</Exercise>

<Exercise title="Read the keys" level="easy">

In the HR schema, which column links an employee to their manager, and what kind of relationship is it?

<Solution>

`EMPLOYEES.manager_id` is a **foreign key to `EMPLOYEES.employee_id`** in the same table, so it is a **recursive (self-referencing)** relationship. King's `manager_id` is NULL because he has no manager.

</Solution>

</Exercise>
