## Oracle Database 11g at a glance

<Ar>نظرة سريعة على Oracle Database 11g</Ar>

The labs follow Oracle's *SQL Fundamentals I* course. Oracle Database 11g is an **object-relational** DBMS (ORDBMS). It is fully relational, and it adds user-defined types, objects and large multimedia data types. Its focus areas are **manageability**, **high availability**, **performance**, **security** and **information integration**. It sits inside a wider product family: Fusion Middleware, Enterprise Manager Grid Control and BI Publisher.

<Ar>تتبع السكاشن العملية مقرر *SQL Fundamentals I* من Oracle. ونظام Oracle Database 11g هو نظام إدارة قواعد بيانات **علائقي كائني (object-relational)** (ORDBMS)؛ فهو علائقي بالكامل، ويضيف أنواعًا يعرّفها المستخدم (user-defined types) وكائنات (objects) وأنواع بيانات كبيرة للوسائط المتعددة. ومجالات تركيزه هي **سهولة الإدارة (manageability)** و**الإتاحة العالية (high availability)** و**الأداء** و**الأمان** و**تكامل المعلومات (information integration)**. وهو جزء من عائلة منتجات أوسع: Fusion Middleware و Enterprise Manager Grid Control و BI Publisher.</Ar>

## Relational concepts

<Ar>مفاهيم النموذج العلائقي</Ar>

Dr. **E. F. Codd** proposed the relational model in **1970**. It has three parts:

<Ar>اقترح الدكتور **E. F. Codd** النموذج العلائقي (relational model) عام **1970**، ويتكون من ثلاثة أجزاء:</Ar>

- a collection of objects, or **relations** (tables),
  <Ar>مجموعة من الكائنات، أي **العلاقات (relations)** (الجداول)،</Ar>
- a set of **operators** that act on relations,
  <Ar>مجموعة من **المؤثرات (operators)** التي تعمل على العلاقات،</Ar>
- **data integrity** rules for accuracy and consistency.
  <Ar>قواعد **سلامة البيانات (data integrity)** لضمان الدقة والاتساق.</Ar>

<Definition term="Relational database" termAr="قاعدة البيانات العلائقية">
  A collection of relations, i.e. <strong>two-dimensional tables</strong>, managed by the Oracle server.

  <Ar>مجموعة من العلاقات (relations)، أي <strong>جداول ثنائية الأبعاد</strong>، يديرها خادم Oracle (Oracle server).</Ar>
</Definition>

Designing a database goes from the client's mental model, to an **entity model** (ER diagram), to a **table model**, to **tables on disk**.

<Ar>يمر تصميم قاعدة البيانات بمراحل: من النموذج الذهني لدى العميل، إلى **نموذج الكيانات (entity model)** (مخطط ER)، إلى **نموذج الجداول (table model)**، ثم إلى **جداول مخزنة على القرص**.</Ar>

### Relating tables

<Ar>ربط الجداول</Ar>

Each row is uniquely identified by its **primary key**, and a **foreign key** links a row to the primary key of a row in another (or the same) table. `EMPLOYEES.department_id` is a foreign key to `DEPARTMENTS.department_id`.

<Ar>يُعرَّف كل صف تعريفًا فريدًا بواسطة **مفتاحه الأساسي (primary key)**، ويربط **المفتاح الأجنبي (foreign key)** الصف بالمفتاح الأساسي لصف في جدول آخر (أو في الجدول نفسه). فالعمود `EMPLOYEES.department_id` مفتاح أجنبي يشير إلى `DEPARTMENTS.department_id`.</Ar>

<SlideFigure page={24} caption="Relational database terminology on the EMPLOYEES table." captionAr="مصطلحات قواعد البيانات العلائقية على جدول EMPLOYEES." />

| # | Term <Ar>المصطلح</Ar> | In the figure <Ar>في الشكل</Ar> |
|---|---|---|
| 1 | **Row** (tuple) <Ar>**الصف (row)** (tuple)</Ar> | All the data for one employee <Ar>كل البيانات الخاصة بموظف واحد</Ar> |
| 2 | **Primary key** column <Ar>عمود **المفتاح الأساسي (primary key)**</Ar> | `EMPLOYEE_ID`, unique for every row <Ar>`EMPLOYEE_ID`، وهو فريد لكل صف</Ar> |
| 3 | **Non-key** column <Ar>عمود **غير مفتاحي (non-key)**</Ar> | e.g. `SALARY` <Ar>مثل `SALARY`</Ar> |
| 4 | **Foreign key** column <Ar>عمود **المفتاح الأجنبي (foreign key)**</Ar> | `DEPARTMENT_ID`, which refers to DEPARTMENTS <Ar>`DEPARTMENT_ID`، ويشير إلى جدول DEPARTMENTS</Ar> |
| 5 | **Field** <Ar>**الحقل (field)**</Ar> | The intersection of one row and one column <Ar>تقاطع صف واحد مع عمود واحد</Ar> |
| 6 | **NULL** field <Ar>حقل **NULL**</Ar> | A field with no value <Ar>حقل ليست فيه قيمة</Ar> |

## SQL

<Ar>لغة SQL</Ar>

**SQL** (Structured Query Language) is the **ANSI standard** language for relational databases. It is efficient, easy to learn, and **functionally complete**: one language defines, retrieves and manipulates data.

<Ar>لغة **SQL** (لغة الاستعلام البنيوية، Structured Query Language) هي اللغة **القياسية وفق ANSI (ANSI standard)** لقواعد البيانات العلائقية. وهي فعّالة وسهلة التعلم و**مكتملة وظيفيًا (functionally complete)**: لغة واحدة تُعرِّف البيانات وتسترجعها وتعالجها.</Ar>

```sql
SELECT department_name
FROM   departments;
```

| Category <Ar>الفئة</Ar> | Statements <Ar>الجمل</Ar> | Purpose <Ar>الغرض</Ar> |
|---|---|---|
| **DML**: data manipulation <Ar>**DML**: لغة معالجة البيانات (data manipulation)</Ar> | `SELECT`, `INSERT`, `UPDATE`, `DELETE`, `MERGE` | Read and change rows <Ar>قراءة الصفوف وتعديلها</Ar> |
| **DDL**: data definition <Ar>**DDL**: لغة تعريف البيانات (data definition)</Ar> | `CREATE`, `ALTER`, `DROP`, `RENAME`, `TRUNCATE`, `COMMENT` | Create and change structures <Ar>إنشاء الهياكل وتعديلها</Ar> |
| **DCL**: data control <Ar>**DCL**: لغة التحكم في البيانات (data control)</Ar> | `GRANT`, `REVOKE` | Give and remove privileges <Ar>منح الصلاحيات وسحبها</Ar> |
| **Transaction control** <Ar>**التحكم في المعاملات (Transaction control)**</Ar> | `COMMIT`, `ROLLBACK`, `SAVEPOINT` | Make DML changes permanent or undo them <Ar>جعل تغييرات DML دائمة أو التراجع عنها</Ar> |

**Tools:** the primary lab tool is **Oracle SQL Developer**, a free graphical IDE. The **SQL\*Plus** command line works too.

<Ar>**الأدوات:** الأداة الأساسية في السكاشن هي **Oracle SQL Developer**، وهي بيئة تطوير رسومية (IDE) مجانية. ويعمل سطر الأوامر **SQL\*Plus** أيضًا.</Ar>

   <Ar>افتح **SQL Worksheet** (ورقة عمل SQL)، واكتب جملة، ثم اضغط **Ctrl+Enter** لتنفيذها.</Ar>

</Steps>

<Takeaways>

- A relational database is a set of **tables** linked by **primary and foreign keys**; Oracle 11g is an **ORDBMS**.
  <Ar>قاعدة البيانات العلائقية مجموعة من **الجداول** المرتبطة عبر **المفاتيح الأساسية والأجنبية (primary and foreign keys)**، ونظام Oracle 11g هو **ORDBMS**.</Ar>
- Oracle ERDs mark UIDs with `#`, mandatory attributes with `*` and optional ones with `o`.
  <Ar>تُعلِّم مخططات ER في Oracle المعرّفات الفريدة (UIDs) بالرمز `#`، والسمات الإلزامية بالرمز `*`، والاختيارية بالرمز `o`.</Ar>
- SQL statements fall into **DML**, **DDL**, **DCL** and **transaction control**.
  <Ar>تنقسم جمل SQL إلى **DML** و**DDL** و**DCL** و**التحكم في المعاملات (transaction control)**.</Ar>
- Every lab queries the **HR** schema, mostly `EMPLOYEES` and `DEPARTMENTS`.
  <Ar>كل السكاشن تستعلم من مخطط **HR**، وغالبًا من `EMPLOYEES` و`DEPARTMENTS`.</Ar>

</Takeaways>

<Exercise title="Classify the statements" titleAr="صنِّف الجمل" level="easy">

Classify each statement: `TRUNCATE`, `MERGE`, `SAVEPOINT`, `REVOKE`, `COMMENT`, `SELECT`.

<Ar>صنِّف كل جملة: `TRUNCATE`، `MERGE`، `SAVEPOINT`، `REVOKE`، `COMMENT`، `SELECT`.</Ar>

<Solution>

`TRUNCATE`: DDL · `MERGE`: DML · `SAVEPOINT`: transaction control · `REVOKE`: DCL · `COMMENT`: DDL · `SELECT`: DML (data retrieval).

<Ar>`TRUNCATE`: من DDL · `MERGE`: من DML · `SAVEPOINT`: من التحكم في المعاملات · `REVOKE`: من DCL · `COMMENT`: من DDL · `SELECT`: من DML (استرجاع البيانات).</Ar>

</Solution>

</Exercise>

<Exercise title="Read the keys" titleAr="اقرأ المفاتيح" level="easy">

In the HR schema, which column links an employee to their manager, and what kind of relationship is it?

<Ar>في مخطط HR، ما العمود الذي يربط الموظف بمديره، وما نوع هذه العلاقة؟</Ar>

<Solution>

`EMPLOYEES.manager_id` is a **foreign key to `EMPLOYEES.employee_id`** in the same table, so it is a **recursive (self-referencing)** relationship. King's `manager_id` is NULL because he has no manager.

<Ar>العمود `EMPLOYEES.manager_id` **مفتاح أجنبي يشير إلى `EMPLOYEES.employee_id`** في الجدول نفسه، لذا فهي علاقة **تكرارية ذاتية المرجع (recursive / self-referencing)**. وقيمة `manager_id` الخاصة بـ King فارغة (NULL) لأنه ليس له مدير.</Ar>

</Solution>

</Exercise>
