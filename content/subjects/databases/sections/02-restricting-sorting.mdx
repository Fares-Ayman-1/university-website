<Objectives>

- Limit the rows a query returns with the **WHERE** clause.
- Use **comparison** conditions: `=`, `<>`, `<`, `<=`, `>`, `>=`, `BETWEEN … AND …`, `IN`, `LIKE`, `IS NULL`.
- Combine conditions with **AND**, **OR** and **NOT**, and apply the **rules of precedence**.
- Sort results with **ORDER BY**: ascending or descending, by alias, by position, and by several columns.

</Objectives>

```sql title="syntax"
SELECT   *|{[DISTINCT] column|expression [alias], ...}
FROM     table
[WHERE   condition(s)]
[ORDER BY {column, expr, alias, position} [ASC|DESC], ...];
```

## The WHERE clause

`WHERE` comes right after `FROM` and keeps only the rows for which the condition is **true**. This is relational **selection** ($\sigma$).

```sql
SELECT employee_id, last_name, job_id, department_id
FROM   employees
WHERE  department_id = 90;
-- 100 King AD_PRES 90 · 101 Kochhar AD_VP 90 · 102 De Haan AD_VP 90
```

<Callout type="warning" title="Strings and dates">

- Character and date values go in **single quotes**.
- Character values are **case-sensitive**: `'Whalen'` matches, `'WHALEN'` doesn't.
- Dates are **format-sensitive**. The default display format is `DD-MON-RR`, e.g. `'17-JUN-03'`.
- You can't use a **column alias** in `WHERE`, because WHERE is evaluated before the SELECT list.

</Callout>

```sql
SELECT last_name, job_id, department_id
FROM   employees
WHERE  last_name = 'Whalen';
```

## Comparison operators

| Operator | Meaning |
|---|---|
| `=` `>` `>=` `<` `<=` | Equal, greater, greater or equal, less, less or equal |
| `<>` (also `!=`) | Not equal |
| `BETWEEN a AND b` | Between two values, **inclusive** |
| `IN (list)` | Matches any value in a list |
| `LIKE` | Matches a character pattern |
| `IS NULL` | Is a NULL value |

```sql
SELECT last_name, salary FROM employees WHERE salary <= 3000;
-- Matos 2600 · Vargas 2500
```

### BETWEEN: ranges (inclusive)

```sql
SELECT last_name, salary
FROM   employees
WHERE  salary BETWEEN 2500 AND 3500;     -- lower limit first!
-- Rajs 3500 · Davies 3100 · Matos 2600 · Vargas 2500
```

`BETWEEN 3500 AND 2500` returns **no rows**: it means `salary >= 3500 AND salary <= 2500`.

### IN: membership in a list

```sql
SELECT employee_id, last_name, salary, manager_id
FROM   employees
WHERE  manager_id IN (100, 101, 201);
```

| EMPLOYEE_ID | LAST_NAME | SALARY | MANAGER_ID |
|---|---|---|---|
| 101 | Kochhar | 17000 | 100 |
| 102 | De Haan | 17000 | 100 |
| 124 | Mourgos | 5800 | 100 |
| 149 | Zlotkey | 10500 | 100 |
| 200 | Whalen | 4400 | 101 |
| 201 | Hartstein | 13000 | 100 |
| 202 | Fay | 6000 | 201 |
| 205 | Higgins | 12000 | 101 |

### LIKE: pattern matching

| Wildcard | Matches |
|---|---|
| `%` | Zero or more characters |
| `_` | Exactly one character |

```sql
SELECT first_name FROM employees WHERE first_name LIKE 'S%';
-- Steven · Shelley

SELECT last_name FROM employees WHERE last_name LIKE '_o%';   -- second letter is "o"
-- Kochhar · Lorentz · Mourgos
```

To search for a literal `%` or `_`, use **ESCAPE**: `WHERE job_id LIKE '%SA\_%' ESCAPE '\'`.

### IS NULL

`= NULL` is **never true**, because NULL compares as unknown. Always test with `IS NULL` / `IS NOT NULL`.

```sql
SELECT last_name, manager_id FROM employees WHERE manager_id IS NULL;
-- King (null)
```

## Logical operators

| Operator | Returns TRUE if… |
|---|---|
| `AND` | **Both** conditions are true |
| `OR` | **Either** condition is true |
| `NOT` | The condition is false (`NOT IN`, `NOT BETWEEN`, `NOT LIKE`, `IS NOT NULL`) |

```sql
SELECT employee_id, last_name, job_id, salary
FROM   employees
WHERE  salary >= 10000
AND    job_id LIKE '%MAN%';
-- 149 Zlotkey SA_MAN 10500 · 201 Hartstein MK_MAN 13000
```

With `OR` instead of `AND`, the same query returns **8** rows: everyone earning at least 10,000 (King, Kochhar, De Haan, Zlotkey, Abel, Hartstein, Higgins) plus Mourgos, a manager earning 5,800.

```sql
SELECT last_name, job_id
FROM   employees
WHERE  job_id NOT IN ('IT_PROG', 'ST_CLERK', 'SA_REP');   -- 10 rows
```

## Rules of precedence

| Order | Operators |
|---|---|
| 1 | Arithmetic |
| 2 | Concatenation `\|\|` |
| 3 | Comparison conditions |
| 4 | `IS [NOT] NULL`, `LIKE`, `[NOT] IN` |
| 5 | `[NOT] BETWEEN` |
| 6 | Not equal to |
| 7 | `NOT` |
| 8 | **`AND`** |
| 9 | **`OR`** |

**AND binds tighter than OR**, so parentheses change the meaning:

```sql
-- (1) means: SA_REP  OR  (AD_PRES AND salary > 15000)
SELECT last_name, job_id, salary FROM employees
WHERE  job_id = 'SA_REP' OR job_id = 'AD_PRES' AND salary > 15000;
-- King 24000 · Abel 11000 · Taylor 8600 · Grant 7000

-- (2) means: (SA_REP OR AD_PRES)  AND  salary > 15000
SELECT last_name, job_id, salary FROM employees
WHERE  (job_id = 'SA_REP' OR job_id = 'AD_PRES') AND salary > 15000;
-- King 24000
```

## Sorting with ORDER BY

`ORDER BY` is **always the last clause**. Rows are sorted ascending (`ASC`, the default) or descending (`DESC`).

```sql
SELECT last_name, job_id, department_id, hire_date
FROM   employees
ORDER BY hire_date;                     -- oldest first

ORDER BY hire_date DESC;                -- newest first
```

You can sort by a **column alias** (ORDER BY runs after SELECT), by **column position**, or by **several columns**:

```sql
SELECT employee_id, last_name, salary*12 annsal
FROM   employees
ORDER BY annsal;                        -- alias

SELECT last_name, job_id, department_id, hire_date
FROM   employees
ORDER BY 3;                             -- 3rd column in the SELECT list

SELECT last_name, department_id, salary
FROM   employees
ORDER BY department_id, salary DESC;    -- by department, then highest salary first
```

| LAST_NAME | DEPARTMENT_ID | SALARY |
|---|---|---|
| Whalen | 10 | 4400 |
| Hartstein | 20 | 13000 |
| Fay | 20 | 6000 |
| Mourgos | 50 | 5800 |
| Rajs | 50 | 3500 |
| … | … | … |
| Grant | (null) | 7000 |

<Callout type="note" title="Where do NULLs go?">
  Oracle sorts NULLs **last** in ascending order and **first** in descending order. That's why Grant, who has no department, is at the bottom. Override it with `NULLS FIRST` or `NULLS LAST`. Other databases (SQLite, MySQL) put NULLs first in ascending order.
</Callout>

<Takeaways>

- `WHERE` filters rows; strings and dates are quoted, strings are case-sensitive, and aliases are not allowed in WHERE.
- `BETWEEN` is inclusive (lower limit first), `IN` tests a list, `LIKE` uses `%` and `_`, and NULL needs `IS NULL`.
- **AND before OR**: use parentheses whenever you mix them.
- `ORDER BY` comes last; it sorts ASC by default and accepts aliases, positions and several columns.

</Takeaways>

## Practice

<Exercise title="Range and pattern" level="easy">

List the last name and salary of employees who earn **between 5,000 and 12,000** and whose last name contains an **"a"**, highest salary first.

<Solution>

```sql
SELECT   last_name, salary
FROM     employees
WHERE    salary BETWEEN 5000 AND 12000
AND      last_name LIKE '%a%'
ORDER BY salary DESC;
```

On the sample: Taylor 8600 · Grant 7000 · Fay 6000. "Abel" starts with a capital A, and LIKE is case-sensitive in Oracle, so it doesn't match. Use `LOWER(last_name) LIKE '%a%'` (Section 3) to ignore case.

</Solution>

</Exercise>

<Exercise title="Fix the logic" level="medium">

"Show sales representatives and the president who earn more than 15,000." A student wrote query (1) above and got four rows. Why, and what's the fix?

<Solution>

`AND` is evaluated before `OR`, so the salary condition only applies to `AD_PRES`, and all sales reps come back regardless of salary. Put the ORs in parentheses: `WHERE (job_id = 'SA_REP' OR job_id = 'AD_PRES') AND salary > 15000`. That returns only King.

</Solution>

</Exercise>

<Exercise title="Commission earners" level="easy">

List the last name, salary and commission of everyone who **earns a commission**, sorted by salary and then commission, both descending.

<Solution>

```sql
SELECT   last_name, salary, commission_pct
FROM     employees
WHERE    commission_pct IS NOT NULL
ORDER BY 2 DESC, 3 DESC;
-- Abel 11000 .3 · Zlotkey 10500 .2 · Taylor 8600 .2 · Grant 7000 .15
```

</Solution>

</Exercise>
